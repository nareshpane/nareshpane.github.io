⚙️From a statement to a checked proof

Lean 4 is both a programming language and an interactive theorem prover. As a language, it defines data, functions, and executable programs. As a prover, it lets you state mathematical claims and build proofs while an editor displays what remains to be shown. The same underlying type system supports both activities.

🧩 Lean concept explorer

One proof, several moving parts

Statement

The claim we want to establish. Types make its domain explicit.

(x y : ℝ) : (x + y)^2 = x^2 + 2*x*y + y^2

A theorem statement, before its proof.

Proof

Evidence that inhabits the proposition being claimed. It can be written directly or built with tactics.

fun h => ⟨h.2, h.1⟩

A proof term for P ∧ Q → Q ∧ P.

Goal

An obligation that has not yet been filled by a proof.

⊢ Q ∧ P

The turnstile is editor notation, not a Lean command.

Hypothesis

Evidence available locally, usually because we assumed a premise.

h : P ∧ Q

We may extract h.1 : P and h.2 : Q.

Tactic

An instruction that constructs part of a proof term and may create smaller goals.

constructor

For Q ∧ P, this creates one goal for Q and another for P.

Proof Term

The logical object ultimately checked, whether written by hand or constructed by tactics.

fun h => ⟨h.2, h.1⟩

This function rearranges the evidence in a conjunction.

Elaborator

Resolves notation, infers omitted arguments, and turns surface syntax into a fully specified expression.

(2 : ℕ) + 3 = 5

The type annotation selects natural-number arithmetic.

Kernel

Checks that the final proof term has the claimed type, relative to the declared definitions and axioms.

proof term : theorem statement

This line is a conceptual schema, not executable Lean.

Mathlib

The mathematical library supplies definitions, structures, proved theorems, and tactics.

hasDerivAt_pow 2 x

A previously proved power rule; the local proof specializes it.

A type

What kind of object?

n : ℕ declares a natural number. f : ℝ → ℝ declares a function from real numbers to real numbers.

A proposition

What is the claim?

P : Prop says that P is a proposition. A proposition is also a type whose inhabitants count as proofs.

A proof

What establishes it?

h : P means that h is evidence for P. It is a term of the type described by that proposition.

Under propositions as types, a proof of \(P\Rightarrow Q\) is a function that turns evidence for \(P\) into evidence for \(Q\). A proof of \(P\land Q\) packages both pieces of evidence. This is why the notation : works for both numbers and hypotheses. See Propositions and Proofs.

⚙️ Inspect elaboration and the trusted kernel

Elaboration fills in omitted arguments, resolves notation, and finds appropriate structures: for example, which addition is meant by +. Tactics are programs that construct proof terms, often by reducing a goal to smaller goals. They do not replace the final check. Lean's small trusted kernel checks that the resulting term has the theorem's type under the declared definitions and axioms. A tactic may fail or produce an invalid candidate; that candidate cannot pass the kernel merely because the tactic said it worked. See the Lean reference on elaboration.

Mathlib supplies definitions, previously proved theorems, and automation for mathematics. Invoking its chain rule is like citing an established theorem, with the additional requirement that the hypotheses and types match exactly. Kernel checking establishes the formal statement; a person must still judge whether that statement captures the intended mathematics.

Why this is more than calculation. A calculator evaluates selected inputs. A symbolic algebra package manipulates expressions. Lean can also compute, but a theorem such as “for every real \(x\)” requires evidence covering all inputs, including any domain assumptions. Testing a million values is not that evidence. Ordinary real-number objects in Mathlib are not just floating-point approximations.

Lean definitions

Theorem hypotheses
In the chain rule, hf and hg supply the two local differentiability assumptions.
Existing theorems

Mathematics

Expand a square

\[\begin{aligned}(x+y)^2&=(x+y)(x+y)\\&=x^2+xy+yx+y^2\\&=x^2+2xy+y^2.\end{aligned}\]

Distribute multiplication over addition, commute \(yx\) to \(xy\), and collect the two middle terms.

Lean
Lean 4 · algebra
theorem square_expansion (x y : ℝ) :
    (x + y)^2 = x^2 + 2*x*y + y^2 := by
  ring

ring normalizes both sides into the same polynomial and constructs a proof of their equality.

A one-line script can request a large amount of elementary reasoning. Its brevity describes how we asked for the proof, not a weakening of what must be checked. It works for all real \(x,y\), not only numerically sampled pairs.

From “P and Q” to “Q and P”

Informal proof. Suppose we have both P and Q. Extract Q, extract P, and put them in the opposite order. The two declarations below encode this same construction using tactics and a direct proof term.

Lean 4 · logic
theorem swap_and (P Q : Prop) : P ∧ Q → Q ∧ P := by
  intro h
  constructor
  · exact h.2
  · exact h.1

example (P Q : Prop) : P ∧ Q → Q ∧ P :=
  fun h => ⟨h.2, h.1⟩

h.1 extracts the first proof from the conjunction and h.2 the second. The brackets ⟨…, …⟩ build a conjunction proof. The dots · focus the two subgoals separately. fun h => … displays the implication's proof as a function.

Level 2 · Discrete mathematics

🔢The first n odd numbers make a square

Claim. The sum of the first \(n\) odd numbers equals \(n^2\), including the empty sum at \(n=0\).

\[S_n=\sum_{k=0}^{n-1}(2k+1)=n^2.\]

Informal proof. Start with \(S_0=0\). Assuming \(S_n=n^2\), the next odd number is \(2n+1\), so \(S_{n+1}=n^2+2n+1=(n+1)^2\). Induction turns these two facts into a proof for every natural number.

Lean 4 · odd sum
theorem sum_first_odds (n : ℕ) :
    (∑ k ∈ Finset.range n, (2*k + 1)) = n^2 := by
  induction n with
  | zero => simp
  | succ n ih =>
      rw [Finset.sum_range_succ, ih]
      ring

Finset.range n is the finite set \(\{0,\ldots,n-1\}\). The sum binder runs over this set. Finset.sum_range_succ separates the last summand; ih then replaces the preceding sum by \(n^2\). These are two explicit rewrites, followed by polynomial algebra.

Successor branch: the new hypothesis

n : ℕ
ih : (∑ k ∈ Finset.range n, (2*k + 1)) = n^2⊢ (∑ k ∈ Finset.range (n+1),
     (2*k + 1)) = (n+1)^2

After rw [Finset.sum_range_succ, ih]

n : ℕ
ih : (∑ k ∈ Finset.range n, (2*k + 1)) = n^2⊢ n^2 + (2*n + 1) = (n+1)^2

ring closes the remaining equality. Here the state uses n+1 for the equivalent successor notation.

The induction hypothesis applies only to the smaller case \(n\). It is not permission to assume the theorem at \(n+1\). The principle of natural-number induction justifies the passage from the two branches to the universal theorem. See Mathematics in Lean: elementary number theory.

Existence carries a witness: even plus even

Here we express “even” directly as “equals twice some natural number.” If \(m=2a\) and \(n=2b\), then \(m+n=2(a+b)\). The witness for the conclusion is \(a+b\).

Lean 4 · even sum
theorem even_plus_even (m n : ℕ)
    (hm : ∃ a, m = 2*a) (hn : ∃ b, n = 2*b) :
    ∃ c, m + n = 2*c := by
  rcases hm with ⟨a, ha⟩
  rcases hn with ⟨b, hb⟩
  use a + b
  rw [ha, hb]
  ring

rcases extracts each witness and its equality. use a + b changes the existential goal into the equality that this witness must satisfy. No search through all natural numbers is needed.

Level 3 · Elementary linear algebra

📐A linear map carries its laws with it

A vector may be a tuple, or a function assigning a coordinate to each index. Fin 2 has indices 0 and 1, so Fin 2 → ℝ represents a real two-coordinate vector. Addition and scalar multiplication are pointwise. ℝ supplies the scalar field; the same ideas work over a general field with suitable typeclass assumptions.

Conventional notationLean representationMeaning
\(v\in\mathbb R^2\)v : Fin 2 → ℝv 0 and v 1 are coordinates.
\(av+bw\)a • v + b • w• denotes scalar multiplication.
\(T:\mathbb R^2\to\mathbb R^2\), linearT : (Fin 2 → ℝ) →ₗ[ℝ] (Fin 2 → ℝ)A function bundled with linearity proofs.
\(M\in\mathbb R^{2\times2}\)Matrix (Fin 2) (Fin 2) ℝRows and columns indexed by Fin 2.

Claims. \(T(u+v)=T(u)+T(v)\), \(T(0)=0\), and \(T(au+bv)=aT(u)+bT(v)\). The first is part of linearity. For the second, \(T(0)=T(0)+T(0)\), then cancellation gives zero. The third combines additivity and compatibility with scalar multiplication.

Lean 4 · linear
example (T : (Fin 2 → ℝ) →ₗ[ℝ] (Fin 2 → ℝ))
    (u v : Fin 2 → ℝ) : T (u + v) = T u + T v := by
  exact T.map_add u v

example (T : (Fin 2 → ℝ) →ₗ[ℝ] (Fin 2 → ℝ)) :
    T 0 = 0 := by
  exact T.map_zero

example (T : (Fin 2 → ℝ) →ₗ[ℝ] (Fin 2 → ℝ))
    (a b : ℝ) (u v : Fin 2 → ℝ) :
    T (a • u + b • v) = a • T u + b • T v := by
  simp only [map_add, map_smul]

The type →ₗ[ℝ] already includes the laws, so T.map_add retrieves one of them. map_zero is a derived library fact. The last proof rewrites using exactly the listed laws; it does not inspect individual coordinates.

The same addition law, in matrix form

For \(M=\begin{pmatrix}2&0\\0&1\end{pmatrix}\), each row is a dot product with the input. Distributing those dot products shows \(M(u+v)=Mu+Mv\).

Lean 4 · matrix
example (u v : Fin 2 → ℝ) :
    (![![2, 0], ![0, 1]] : Matrix (Fin 2) (Fin 2) ℝ).mulVec
      (u + v) =
    (![![2, 0], ![0, 1]] : Matrix (Fin 2) (Fin 2) ℝ).mulVec u +
    (![![2, 0], ![0, 1]] : Matrix (Fin 2) (Fin 2) ℝ).mulVec v := by

![…] constructs a finite coordinate vector; nesting it gives matrix rows. mulVec is matrix–vector multiplication. _ asks elaboration to infer the matrix from the goal. The general Matrix.mulVec_add supplies the row-wise distributivity argument.

Level 4 · Univariate calculus

📈A derivative is a limit statement

🧠 Intuition📐 Statement💻 Representation🧩 Construction⚙️ Kernel check
📐 Mathematics

Claim. The function \(f(t)=t^2\) has derivative \(2x\) at every real point \(x\). Expanding the difference quotient gives

\[\frac{(x+h)^2-x^2}{h}=2x+h\longrightarrow 2x\quad(h\to0,\ h\ne0).\]

HasDerivAt f d x says that the actual derivative of \(f\) at \(x\) is \(d\). Conceptually, \(f(x+h)=f(x)+dh+r(h)\) with \(|r(h)|/|h|\to0\). This simultaneously asserts differentiability and identifies its value. Manipulating the symbol \(f'\) alone would not establish that limit.

💻 Lean
Lean 4 · square deriv
theorem square_derivative (x : ℝ) :
    HasDerivAt (fun t : ℝ => t^2) (2*x) x := by
  simpa using (hasDerivAt_pow 2 x)

hasDerivAt_pow 2 x supplies the proved power rule with derivative \(2x^{2-1}\). simpa simplifies the exponent, cast, and first power to match \(2x\). The local proof uses this theorem; it does not reprove the underlying limit.

A product: polynomial times exponential

Informal calculation. Differentiate each factor once and add the two contributions:

\[\frac{d}{dx}(x^2e^x)=(2x)e^x+x^2e^x.\]
Lean 4 · product deriv
theorem square_times_exp (x : ℝ) :
    HasDerivAt (fun t : ℝ => t^2 * Real.exp t)
      (2*x * Real.exp x + x^2 * Real.exp x) x := by
  exact (square_derivative x).mul (Real.hasDerivAt_exp x)

square_derivative x reuses our preceding result; Real.hasDerivAt_exp x supplies the exponential's derivative; .mul combines their evidence using the product rule. Function multiplication is pointwise, so the result matches the displayed lambda expression.

Level 5 · Multivariable calculus

∂The best linear approximation near a point

For f : ℝ → ℝ, a derivative is a scalar slope; multiplying by that scalar is a linear map. For f : E → F, where E and F are normed real vector spaces, the first-order change must be a map carrying an input displacement to an output displacement.

\[f(x+h)=f(x)+A(h)+r(h),\qquad\lim_{h\to0,\ h\ne0}\frac{\|r(h)\|}{\|h\|}=0.\]

This is Fréchet differentiability. The approximating map \(A:E\to F\) is continuous and linear. “Best” here means that the error is smaller than first order, not that we fitted a regression line. In finite dimensions, A can be represented by the Jacobian matrix. All sufficiently small displacements must satisfy this estimate, not only displacements along one chosen direction. Mathlib encodes it as HasFDerivAt f A x.

A complete formal example: every affine map has constant derivative

📐 Mathematics

Claim. If \(f(z)=Az+b\) on \(\mathbb R^2\), its derivative at every x is A. Indeed, \(f(x+h)-f(x)-Ah=0\); there is no residual at all.

💻 Lean
Lean 4 · affine
theorem affine_derivative
    (A : (ℝ × ℝ) →L[ℝ] (ℝ × ℝ)) (b x : ℝ × ℝ) :
    HasFDerivAt (fun z => A z + b) A x := by
  exact A.hasFDerivAt.add_const b

ℝ × ℝ is another representation of a two-coordinate vector; Mathlib equips it with a product norm. →L[ℝ] denotes a continuous real-linear map. Lean coerces A to a function when writing A z. A.hasFDerivAt states that a continuous linear map is its own derivative; .add_const b preserves it under translation. No coordinates or matrix entries are needed in the proof.

Level 6 · Differential equations

🌊Verify a solution before claiming uniqueness

Problem. Given real constants a and c, verify that \(y(t)=ce^{at}\) satisfies \(y'(t)=ay(t)\) and \(y(0)=c\).

Mathematics

Differentiate the candidate

\[\begin{aligned}y'(t)&=c\,e^{at}\,a\\&=a(ce^{at})=ay(t),\\y(0)&=ce^0=c.\end{aligned}\]

The derivative of \(at\) is a; the chain rule contributes that factor. Multiplication by c scales the derivative.

What is being proved?

Every time, every parameter

The parameters (a c t : ℝ) are arbitrary. A HasDerivAt conclusion gives both differentiability and the desired equation at that time.

No numerical time steps or approximate exponential values enter the proof.

Lean 4 · ode
theorem exponential_solution (a c t : ℝ) :
    HasDerivAt (fun s : ℝ => c * Real.exp (a*s))
      (a * (c * Real.exp (a*t))) t := by
  have h : HasDerivAt (fun s : ℝ => a*s) a t := by
    simpa using (hasDerivAt_id t).const_mul a
  simpa only [mul_comm, mul_left_comm, mul_assoc] using
    h.exp.const_mul c

example (a c : ℝ) : c * Real.exp (a*0) = c := by
  simp

have h creates the inner derivative fact. h.exp applies the exponential chain rule; .const_mul c scales it. The final simplifier uses commutativity and associativity to put the derivative into the exact form \(a\,y(t)\). The last declaration separately checks the initial value.

Verification versus existence and uniqueness. This explicit construction supplies a solution for every a and c, so it also gives existence for this particular initial-value problem. It does not show that an arbitrary other solution must equal it, nor does it establish a general ODE existence theorem. One informal uniqueness proof differentiates \(e^{-at}y(t)\), shows its derivative is zero, and uses constancy on an interval. That additional argument is not formalized here.

For a general vector field \(y'=F(t,y)\), finding even one formula may be impossible. Existence and uniqueness then require separate analysis and suitable hypotheses; a plot of one candidate cannot substitute for them.

Level 7 · Graduate analysis

🎓The chain rule on normed spaces

🧠 Intuition📐 Statement💻 Representation🧩 Construction⚙️ Kernel check

Now the variables can be functions or infinite sequences, not only coordinate vectors. Let E, F, and G be real normed vector spaces. If f is Fréchet differentiable at x with derivative A, and g is Fréchet differentiable at f(x) with derivative B, then

\[E\xrightarrow{f}F\xrightarrow{g}G,\qquad D(g\circ f)(x)=Dg(f(x))\circ Df(x)=B\circ A.\]

This is the chain rule used in infinite-dimensional analysis. It applies, for example, when E is a Banach space of functions. Completeness is not needed for this theorem: every Banach space is a normed space, but the statement below deliberately assumes only the weaker structure.

Lean 4 · chain
theorem frechet_chain_rule
    {E F G : Type*}
    [NormedAddCommGroup E] [NormedSpace ℝ E]
    [NormedAddCommGroup F] [NormedSpace ℝ F]
    [NormedAddCommGroup G] [NormedSpace ℝ G]
    (f : E → F) (g : F → G) (x : E)
    (A : E →L[ℝ] F) (B : F →L[ℝ] G)
    (hf : HasFDerivAt f A x)
    (hg : HasFDerivAt g B (f x)) :
    HasFDerivAt (g ∘ f) (B.comp A) x := by
  exact hg.comp x hf

Part of the statementMathematical role

🎓 Open the analytic proof and Mathlib’s role

Why the mathematics is more than a notation change

Write the two local expansions, with remainders that are little-o of their inputs:

\[\begin{aligned}f(x+h)&=f(x)+Ah+r(h),\\g(f(x)+k)&=g(f(x))+Bk+s(k).\end{aligned}\]

Substituting \(k=Ah+r(h)\) gives

\[g(f(x+h))-g(f(x))-BAh=B(r(h))+s(Ah+r(h)).\]

Continuity of the linear maps gives bounds \(\|Av\|\leq C_A\|v\|\) and \(\|Bw\|\leq C_B\|w\|\). The first term on the right is therefore \(o(\|h\|)\). Also \(\|Ah+r(h)\|=O(\|h\|)\), so the second is \(o(\|h\|)\). This is the needed remainder estimate for the composition, even in infinite dimensions.

Why continuous linear maps? On finite-dimensional normed spaces every linear map is continuous. In infinite dimensions linearity alone need not give the bounds above. The L in →L[ℝ] records precisely the analytic control needed to transfer small errors through an operator.

Mathlib versus the local proof. HasFDerivAt.comp provides the general composition theorem. hg.comp x hf specializes it to these maps, this point, and these hypotheses. The local proof supplies the correctly typed data; Mathlib supplies the already formalized analytic argument. This is a formal application of a graduate theorem, not a new proof from first principles.

Reproducibility

💻Read the statements, then run the source

lean_examples.lean contains all substantive Lean blocks on this page, with import Mathlib, a namespace to avoid name collisions, and open scoped BigOperators for sum notation. Examples using an earlier named theorem should be run in order.

Inside an existing Lean 4 project that already depends on Mathlib, place the downloaded file in the project directory and run:

Terminal · existing Mathlib project
lake env lean lean_examples.lean

The project's Lean toolchain must match its Mathlib dependency. This page does not pin or bundle a toolchain. Documentation review is not a substitute for compilation: until the file has been checked in such a project, its elaboration remains unverified. No sorry placeholders or extra axioms are used in the examples.

A useful reading habit. First identify the quantified variables and hypotheses. Next say the conclusion in ordinary mathematics. Finally, check how each tactic transforms the goal or which library theorem it invokes. A short proof becomes understandable once its imported mathematical work is visible.
