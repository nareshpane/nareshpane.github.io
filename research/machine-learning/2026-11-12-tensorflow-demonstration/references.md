# Sources and implementation notes

Checked against primary sources on **12 November 2026**. These references support the mathematical methods and public APIs; they do not supply the project's synthetic observations or imply that this project's models have been trained. All exposition, synthetic generators, and editable illustrations were developed for this monograph. No external photographs or datasets are required.

## Official software documentation

1. **TensorFlow installation.** [Install TensorFlow with pip](https://www.tensorflow.org/install/pip), [tested build configurations](https://www.tensorflow.org/install/source), and [TensorFlow 2.20.0 release metadata and wheels](https://pypi.org/project/tensorflow/2.20.0/). The reproducibility target is TensorFlow **2.20.0**, released 13 August 2025; this is a deliberate stable version pin, not a claim that it is the newest release. The tested-build table lists Python 3.9–3.13 for this version, and the maintainer-uploaded release includes a CPython 3.13 Windows x86-64 wheel. Parts of the general installation page still list an older Python range; release-specific metadata is the more precise compatibility source. Native Windows CUDA support ended with TensorFlow 2.10. Modern NVIDIA GPU instructions use Linux or WSL2. CPU is the default here.

2. **TensorFlow automatic differentiation.** [Introduction to gradients and automatic differentiation](https://www.tensorflow.org/guide/autodiff). Source for `tf.GradientTape`, watched variables, gradients, and reverse accumulation. A tape differentiates recorded TensorFlow operations. Conversion to NumPy inside the differentiated computation disconnects that path. Differentiating a nonscalar target with `gradient` aggregates contributions; this matters for interpreting derivatives of batched outputs.

3. **Higher derivatives.** [Advanced automatic differentiation](https://www.tensorflow.org/guide/advanced_autodiff). Source for nested tapes and Jacobians. To compute a second derivative, the outer coordinate tape must record the first-derivative calculation and the relevant slicing. The parameter tape must enclose residual construction so that optimization differentiates through the differential operator. A row-independent dense network permits the sum-gradient shortcut for pointwise coordinate derivatives. Batch normalization or attention across evaluation points invalidates that argument.

4. **Input pipelines.** [The `tf.data` guide](https://www.tensorflow.org/guide/data). Source for construction, batching, shuffling, prefetching, and dataset transformations. Dataset speed and deterministic execution are distinct concerns; shuffling training windows is acceptable only after chronological membership has been fixed.

5. **Forecasting.** [Time-series forecasting tutorial](https://www.tensorflow.org/tutorials/structured_data/time_series). Source for windowed supervised learning, chronological separation, normalization, baselines, recurrent models, and multiple-output forecasting. This monograph uses its own synthetic energy process and explicit origin-index conventions.

6. **Keras 3 compatibility.** [Migrating Keras 2 code to Keras 3](https://keras.io/guides/migrating_to_keras_3/) and [serialization and saving](https://keras.io/guides/serialization_and_saving/). Use one consistent Keras API family with the TensorFlow backend. A native `.keras` archive is suitable for `save`/`load_model`; serving export uses `export`, a different operation. Custom losses need registration or an explicit `custom_objects` mapping for a compiled reload. Loading with `compile=False` is sufficient for prediction-only round-trip verification. Explicit `jit_compile=False` avoids unsupported XLA string operations in a text model.

7. **Text encoding.** [`TextVectorization`](https://keras.io/api/layers/preprocessing_layers/text/text_vectorization/), [`Embedding`](https://keras.io/api/layers/core/embedding/), and [global average pooling](https://keras.io/api/layers/pooling_layers/global_average_pooling1d/). Integer vectorization reserves 0 for padding and 1 for the unknown token; these occupy vocabulary entries. Adapt the vocabulary on training text only. `mask_zero=True` must be paired with a downstream layer that consumes the mask if padding is to be excluded from pooling. Default punctuation stripping deletes punctuation rather than replacing every punctuation mark with a space; document preprocessing exactly.

8. **Reproducibility.** [Keras Python and NumPy utilities](https://keras.io/api/utils/python_utils/) and [`enable_op_determinism`](https://www.tensorflow.org/api_docs/python/tf/config/experimental/enable_op_determinism). Set Python, NumPy, and TensorFlow seeds through supported utilities, and seed independently created NumPy `Generator` instances explicitly. Deterministic kernels do not guarantee identical results across different hardware, software versions, or arithmetic precisions.

9. **Related official tutorials.** [TensorFlow image tutorials](https://www.tensorflow.org/tutorials/images) and [TensorFlow text tutorials](https://www.tensorflow.org/text/tutorials). Further learning resources rather than sources of this project's original experiments.

## Original scientific publications

10. **Backpropagation.** David E. Rumelhart, Geoffrey E. Hinton, and Ronald J. Williams (1986). *Learning representations by back-propagating errors*. **Nature 323**, 533–536. Published 9 October 1986. [Publisher/DOI](https://doi.org/10.1038/323533a0); [author's bibliography](https://www.cs.toronto.edu/~hinton/backprop.html). Supports reverse application of the chain rule through multilayer networks. This citation is not a claim that reverse differentiation originated uniquely with this paper.

11. **Convolutional networks.** Yann LeCun, Léon Bottou, Yoshua Bengio, and Patrick Haffner (1998). *Gradient-based learning applied to document recognition*. **Proceedings of the IEEE 86**(11), 2278–2324. [DOI](https://doi.org/10.1109/5.726791); [author-hosted publication record](https://bottou.org/papers/lecun-98h). Supports local receptive fields and shared trainable filters. The operation implemented by common neural libraries is cross-correlation; flipping the kernel is needed for the mathematical convolution convention.

12. **U-Net.** Olaf Ronneberger, Philipp Fischer, and Thomas Brox (2015). *U-Net: Convolutional Networks for Biomedical Image Segmentation*. **MICCAI 2015**, LNCS 9351, 234–241. [Author publication page](https://lmb.informatik.uni-freiburg.de/people/ronneber/u-net/); [arXiv:1505.04597](https://arxiv.org/abs/1505.04597), first submitted 18 May 2015; [DOI](https://doi.org/10.1007/978-3-319-24574-4_28). The project's compact same-padded encoder–decoder is U-Net-inspired; it is not an exact replication of the original architecture, training set, or biomedical results.

13. **LSTM.** Sepp Hochreiter and Jürgen Schmidhuber (1997). *Long Short-Term Memory*. **Neural Computation 9**(8), 1735–1780. [DOI](https://doi.org/10.1162/neco.1997.9.8.1735); [author-hosted paper](https://people.idsia.ch/~juergen/lstm1997-2024head.pdf). Source for gated recurrent memory. Later implementations contain refinements; a modern forget-gate description should not be attributed verbatim to the original architecture.

14. **Physics-informed neural networks.** Maziar Raissi, Paris Perdikaris, and George E. Karniadakis (2019). *Physics-informed neural networks: A deep learning framework for solving forward and inverse problems involving nonlinear partial differential equations*. **Journal of Computational Physics 378**, 686–707. [DOI](https://doi.org/10.1016/j.jcp.2018.10.045); [authors' project and bibliography](https://maziarraissi.github.io/PINNs/). The DOI contains 2018, while the journal volume is dated 2019. Supports optimization combining data/condition penalties with automatically differentiated PDE residuals. The one-dimensional heat benchmark and implementation here are original educational experiments, not the paper's reported numerical study.

15. **Split-conformal construction.** Anastasios N. Angelopoulos and Stephen Bates (2021; revised 2022). *A Gentle Introduction to Conformal Prediction and Distribution-Free Uncertainty Quantification*. [arXiv:2107.07511](https://arxiv.org/abs/2107.07511), first submitted 15 July 2021, version 6 dated 7 December 2022; [full text](https://arxiv.org/html/2107.07511v6). Explains finite-sample rank correction, marginal coverage, calibration, and the role of exchangeability. For absolute residuals and `m` calibration examples, use order statistic `ceil((m+1)*(1-alpha))`, indexed from 1; if that rank exceeds `m`, the finite-sample interval is unbounded. Selecting a quantile by linear interpolation can implement a different rule. Horizon-wise intervals target marginal coverage for each horizon, not simultaneous coverage of an entire trajectory.

16. **Dependence caveat.** Victor Chernozhukov, Kaspar Wüthrich, and Yinchu Zhu (2018). *Exact and Robust Conformal Inference Methods for Predictive Machine Learning with Dependent Data*. **Proceedings of Machine Learning Research 75**, 732–749, COLT 2018. [Conference publication and paper](https://proceedings.mlr.press/v75/chernozhukov18a.html); [arXiv:1802.06300](https://arxiv.org/abs/1802.06300). Their dependent-data procedures require their own conditions and construction. A simple chronological absolute-residual interval is useful empirically but does not inherit exchangeable-data coverage guarantees automatically. This monograph reports empirical holdout coverage rather than claiming to implement this paper's method.

## Revision sources: alternatives, performance, and deployment

The following official documentation was checked on **12 November 2026** for the revised comparison of computational approaches. These are sources for capabilities and qualified mechanisms, not measurements of this monograph's programs. **No TensorFlow-versus-library performance benchmark was run for this revision.** Live documentation may describe newer versions than the pinned experimental target.

17. **Dispatch overhead and problem size.** [NumPy API on TensorFlow, performance comparisons](https://www.tensorflow.org/guide/tf_numpy#performance_comparisons). The guide explains that TensorFlow uses optimized kernels on supported devices, while its operation-dispatch overhead can dominate small workloads and allow NumPy to perform better. Its downloadable size-dependent experiment is a documented example, not evidence for a universal ranking or a speed multiplier for this project. Compare equivalent dtype, algorithm, device placement, and work before interpreting timings.

18. **Tracing and Python overhead.** [Better performance with `tf.function`](https://www.tensorflow.org/guide/function). A function traces TensorFlow operations into a reusable dataflow graph; this can reduce repeated Python dispatch. Tracing has a cost. Changes in input signatures or Python-valued arguments can trigger retracing, which can make execution slower. The guide's convolution example also demonstrates that wrapping a few expensive operations may provide little benefit. `tf.function` tracing and optional XLA compilation are distinct mechanisms; a graph wrapper is not an unconditional acceleration switch.

19. **Input pipeline overlap, parallel mapping, and buffers.** [Better performance with the `tf.data` API](https://www.tensorflow.org/guide/data_performance). Its artificial delayed-I/O example illustrates why prefetching can overlap data preparation with model execution. It also illustrates parallel reading/interleaving, `map(..., num_parallel_calls=...)`, and batching before a vectorizable map to reduce per-call scheduling overhead. Prefetch, shuffle, interleave, and cache retain data and therefore affect memory usage. Overlap does not remove slow storage or preprocessing, and changing operation order must preserve the intended transformations. This monograph does not reproduce the guide's timings or treat them as measurements on its synthetic data.

20. **Find the actual bottleneck.** [Optimize TensorFlow performance using the Profiler](https://www.tensorflow.org/guide/profiler) and [GPU performance analysis](https://www.tensorflow.org/guide/gpu_performance_analysis). The Profiler separates input, kernel launch, host computation, device computation, and other costs. The GPU guide explicitly warns that transfers and launch overhead can outweigh benefits for small models. Larger batches/vectorized operations may improve utilization, subject to memory and statistical implications. Profiling is needed to identify whether input preparation, numerous small operations, transfers, or arithmetic limits a particular run. Avoid profiling initial setup batches when estimating steady-state behavior; cold-start behavior is a separate quantity worth reporting when relevant.

21. **Warm-up and synchronization for timing.** [`tf.test.experimental.sync_devices`](https://www.tensorflow.org/api_docs/python/tf/test/experimental/sync_devices). The API documents asynchronous GPU execution and a warm-up/timing example that synchronizes before and after timed work. It must be called eagerly, outside a `tf.function`. Timing only the Python return can measure queue submission rather than finished execution. A reproducible comparison should state warm-up policy, repeated measurements, device, dtype, shapes, thread configuration, software versions, and whether allocation and host/device transfer are included. Materializing an output on the CPU can introduce a synchronization and transfer cost; that cost belongs in an explicitly defined end-to-end measurement rather than being silently mixed with device-only computation.

22. **Save an editable model versus export inference.** [Keras serialization and saving](https://keras.io/guides/serialization_and_saving/) and [model export for inference](https://keras.io/api/models/model_saving_apis/export/). A native `.keras` archive stores a Keras model for `load_model`; exporting a TensorFlow SavedModel supplies inference endpoints loaded with `tf.saved_model.load` or used by a compatible serving system. These are different artifacts and reload APIs. Saving a model does not itself deploy an endpoint or provide a browser inference runtime. Export requires compatible operations, input signatures, preprocessing state, and a tested target environment. The revision preserves the existing program's `.keras` round-trip checks and does not claim to have validated a serving deployment.

23. **NumPy is compiled array computation, not a Python loop requirement.** [What is NumPy?](https://numpy.org/doc/stable/user/whatisnumpy.html) and [`numpy.linalg.lstsq`](https://numpy.org/doc/stable/reference/generated/numpy.linalg.lstsq.html). NumPy's array operations commonly execute compiled routines. `lstsq` directly solves a linear least-squares problem, including rank-deficient/overdetermined cases under its documented numerical convention. A simple regression need not use gradient descent or any machine-learning framework. The manual-gradient example in this revision teaches the optimization calculation; it is not a recommendation to replace a suitable linear solver with thousands of updates.

24. **SciPy supplies numerical methods independently of TensorFlow.** [Optimization tutorial](https://docs.scipy.org/doc/scipy/tutorial/optimize.html), [`scipy.ndimage.convolve`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.convolve.html), and [`scipy.sparse.linalg.spsolve`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.linalg.spsolve.html). SciPy provides optimization interfaces, image filtering, and sparse linear solves. These are useful ingredients for conventional image processing and discretized differential equations. A sparse solver solves the assembled linear system; it does not automatically select a physically appropriate PDE discretization, boundary conditions, or error criterion. SciPy's mathematical convolution convention and boundary handling must be distinguished from the neural cross-correlation convention.

25. **Classical text classification.** [Scikit-learn text feature extraction](https://scikit-learn.org/stable/modules/feature_extraction.html#text-feature-extraction) and [`LogisticRegression`](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html). Count/TF-IDF sparse representations and regularized logistic regression provide a complete non-neural classification route; vocabulary and IDF statistics still must be learned from training data only. The current project's executed language baseline remains its own multinomial Naive Bayes implementation. The additional library examples are alternatives, not newly measured comparisons against its neural classifier.

26. **Forecasting without a recurrent network.** [Scikit-learn lagged-features forecasting example](https://scikit-learn.org/stable/auto_examples/applications/plot_time_series_lagged_features.html). This official example constructs lagged features for a gradient-boosting regressor and contrasts random splitting with time-respecting evaluation. It is a concrete documented demonstration of a forecasting method that does not require TensorFlow. Its scores and dataset are not this monograph's demand experiment; the relevant lesson is to preserve information timing and evaluate an appropriate baseline, irrespective of estimator.

27. **Another automatic-differentiation framework.** [PyTorch automatic differentiation tutorial](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html). PyTorch records operations into a differentiable computation graph and computes parameter derivatives through `torch.autograd`; its surrounding ecosystem supplies layers, optimizers, and data loading. TensorFlow is not the sole way to build or train deep networks. Framework capabilities do not determine which will be faster, easier to deploy, or more appropriate for a particular codebase without further requirements and measurements.

28. **Composable differentiation and compilation in JAX.** [JAX automatic differentiation](https://docs.jax.dev/en/latest/automatic-differentiation.html) and [JIT compilation](https://docs.jax.dev/en/latest/jit-compilation.html). `grad` transforms scalar-valued functions into gradient functions and can be composed for higher derivatives; `jit` supplies compilation, with tracing/compilation constraints and startup costs. A JAX implementation can therefore express parameter optimization and coordinate derivatives for a PINN. Ordinary NumPy calls and arbitrary Python side effects are not automatically interchangeable with transformable JAX computations.

**Derivative distinction.** Sources 2–3 and 27–28 concern automatic differentiation through implemented elementary operations. This applies chain-rule derivative rules to an executed program, with floating-point limitations. It is neither finite-difference estimation by input perturbation nor symbolic production of an algebraic formula. A finite-difference heat solver discretizes the physical field on a grid; a PINN's autodiff differentiates its neural approximation. They approximate the same benchmark through different mathematical constructions, and no general performance superiority follows from the framework choice.
