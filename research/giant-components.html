Introduction · Why n/2 matters

Edges, cycles and the critical window

The average degree at edge count \(m\) is \(2m/n\). Thus \(m=n/2\) is the point where average degree reaches one. Below the transition, components mostly resemble trees with occasional cycles. In the critical window \(m=n/2+O(n^{2/3})\), component sizes and cyclic structures fluctuate substantially. Critical large components have scale \(n^{2/3}\); a giant in the macroscopic sense has size proportional to \(n\). Being complex does not by itself make a component a giant.

The classical permutation process gives a uniform simple graph \(G(n,m)\) at each accepted edge count. The 1993 paper also uses a weighted multigraph process. Their limits coincide for the two events studied here, while their finite-size probabilities can differ. All results below keep the processes separate. See the paper's introduction and Section 1.

A component's cycle count

For a connected component \(H\) with \(v\) vertices and \(e\) edges, a spanning tree uses exactly \(v-1\) edges. The remaining edges give the dimension of its cycle space, including loops and parallel-edge cycles in a multigraph:

\[\beta(H)=e-v+1.\]
Tree · β = 0v = 4, e = 3
Unicyclic · β = 1v = 3, e = 3
Bicyclic · β = 2v = 4, e = 5 · complex
Tricyclic · β = 3v = 4, e = 6 · complex
Bicyclic components are already complex. The complex condition is \(e>v\), equivalently \(\beta\ge2\). Size \(v\), edge count \(e\), cycle rank \(\beta\), and signed component excess \(e-v=\beta-1\) measure different things.

For a tree, signed component excess is −1; it is zero for a unicyclic component and positive for a complex component. Section 13's graph excess excludes the tree deficit. If \(t\) is the number of tree components, it is

\[r(G)=m-n+t=\sum_H\max\{e_H-v_H,0\}.\]

This differs both from \(m-n\) and from total cycle rank \(\sum_H\beta(H)=m-n+k\), where \(k\) counts all components. The notation \(C_j\) in the paper describes connected components with positive excess \(j\), hence \(j+1\) independent cycles.

What one accepted edge does

If its endpoints already share a component, \(v\) stays fixed and \(e\) increases by one: \(\beta\) increases by one. This includes a self-loop. If it joins two components,

\[v'=v_1+v_2,\qquad e'=e_1+e_2+1,\qquad \beta'=\beta_1+\beta_2.\]

A merger adds no new independent cycle. Joining two unicyclic components nevertheless produces a bicyclic component. Joining two complex components reduces the current complex-component count from two to one; it cannot undo their earlier coexistence.

Experiment 1 · Section 11, Equation (11.7)

A critical snapshot with at most two cycles per component

Let \(A_n\) be the event that every connected component has \(\beta\le2\) after exactly \(m=\lfloor n/2\rfloor\) accepted edges. Multiple bicyclic components are permitted. One tricyclic component is enough to fail.

Original-paper corollary · verbatim
“Corollary. The probability that a random graph or multigraph with \(n\) vertices and \(\frac12 n\) edges has only acyclic, unicyclic, and bicyclic components is
\[\sqrt{\frac23}\cosh\sqrt{\frac5{18}}+O(n^{-1/3})\approx0.9325.\text{”}\tag{11.7}\]
Svante Janson, Donald E. Knuth, Tomasz Łuczak, and Boris Pittel, The Birth of the Giant Component (1993), Section 11, Corollary, Equation (11.7), printed/PDF page 51. Read the complete statement and proof.

The quoted corollary is transcribed from the supplied screenshot; the event definition and discussion here are original exposition.

The 93.25% figure is a limiting probability, not an exact finite-\(n\) value. The \(O(n^{-1/3})\) statement bounds the asymptotic discrepancy in order; it provides neither a numerical error bar nor a known sign. The experiment uses the floor convention for odd \(n\); all 15 published sizes happen to be even.

Understanding the Asymptotic Error Term \(O(n^{-1/3})\)

Writing \(p_\infty\) for the limiting probability in Equation (11.7), the notation \(O(n^{-1/3})\) describes an asymptotic bound on the discrepancy between the finite-\(n\) probability \(\Pr(A_n)\) and that limit as the number of vertices grows. Under the assumptions of the corollary, there exist constants \(C>0\) and \(n_0\) for which

\[\left|\Pr(A_n)-p_\infty\right|\le Cn^{-1/3}\qquad\text{for all }n\ge n_0.\]

The exponent \(-1/3\) gives a polynomially decreasing upper bound: increasing \(n\) by a factor of eight halves the \(n^{-1/3}\) term. Big-O notation supplies neither the numerical constant \(C\), an exact finite-size correction, nor the direction of the discrepancy, so \(n^{-1/3}\) itself should not be treated as the exact probability error. This asymptotic approximation error is distinct from Monte Carlo sampling uncertainty, which depends on the number of independent simulation trials and can be assessed using binomial standard errors or confidence intervals.

From connected-component enumeration to cosh

The following coefficient identities specify the combinatorial calculation. The reduction of their coefficients to a critical asymptotic law is the paper's technical step; the series summation following that law is shown explicitly here. Write \(T\) for the rooted labelled-tree generating function and \(U\) for unrooted trees. In the weighted multigraph model,

\[T(z)=ze^{T(z)},\quad U(z)=T(z)-\tfrac12T(z)^2,\quad V(z)=\tfrac12\log\frac1{1-T(z)}.\] \[W(z)=\frac5{24}(1-T)^{-3}-\frac7{24}(1-T)^{-2}+\frac1{12}(1-T)^{-1}.\]

Here \(V\) enumerates connected unicyclic structures and \(W\) enumerates connected bicyclic structures. For exactly \(r\) bicyclic components and none of higher order, the number of tree components must be \(n-m+r\): summing \(e-v\) over components gives \(m-n=-t+r\). The labelled set construction then leads to the probability coefficient (11.2):

\[\frac{2^m m!n!}{n^{2m}}[z^n]\frac{U(z)^{n-m+r}}{(n-m+r)!}\,e^{V(z)}\frac{W(z)^r}{r!}.\]

The factor \(e^V\) allows any number of unicyclic components; \(W^r/r!\) specifies exactly \(r\) bicyclic ones. Component labels are handled by the exponential generating functions. Near \(T=1\), the strongest singularity in \(W\) has coefficient \(5/24\) and order three. Theorem 4, using Lemma 3, evaluates the coefficient for fixed \(r\) and \(m=n/2+O(n^{1/3})\):

\[\Pr(\text{exactly }r\text{ bicyclic, none higher})=\sqrt{\frac23}\frac{(5/18)^r}{(2r)!}+O(n^{-1/3}).\]

The factorial is consistent with the gamma duplication identity

\[\Gamma(r+\tfrac12)=\frac{(2r)!\sqrt\pi}{4^r r!}.\]

The cosh step is now an elementary calculation:

\[\sum_{r=0}^\infty\sqrt{\frac23}\frac{(5/18)^r}{(2r)!}=\sqrt{\frac23}\sum_{r=0}^\infty\frac{\bigl(\sqrt{5/18}\bigr)^{2r}}{(2r)!}=\sqrt{\frac23}\cosh\sqrt{\frac5{18}}.\]

Summing fixed-\(r\) limits alone does not prove this equals the event limit: probability could escape to configurations with unbounded \(r\). The corollary supplies the needed uniform convergence argument in (11.8)–(11.9). Section 12 offers another route through the joint component distribution and its normalization in Section 13. This is a proof roadmap, not a reproduction of the full contour analysis. Sections 11–13.

Why the simple-graph limit agrees

For simple graphs, unicyclic structures exclude loops and double edges, giving \(\widehat V=V-T/2-T^2/4\); bicyclic enumeration changes too, while its dominant singular term remains \((5/24)(1-T)^{-3}\). At the critical singularity the exponential correction contributes \(e^{-3/4}\). The simple-graph probability normalization contributes the compensating \(e^{3/4}\). Equation (11.6) therefore has the same leading limit as (11.2), without asserting finite-size equality.

Experiment 2 · Section 27, Theorem 15

Never two complex components, over the whole history

Let \(C_m\) count components with \(e-v>0\) immediately after accepted edge \(m\). Define the history event \(B_n=\{C_m\le1\text{ for every }m\}\). A process fails on the first accepted edge with \(C_m\ge2\), even if those components merge one edge later.

Original-paper introduction · verbatim
“The actual probability that an evolving graph never has two complex components approaches the limiting value \(5\pi/18\approx0.8727\)”
Svante Janson, Donald E. Knuth, Tomasz Łuczak, and Boris Pittel, The Birth of the Giant Component (1993), Introduction, printed/PDF page 3. Read the full passage. The formal result and proof appear in Section 27, Theorem 15, page 115.

Selected verbatim excerpt from the introduction of the original paper.

\[\lim_{n\to\infty}\Pr(B_n)=\frac{5\pi}{18}=0.8726646259971648\ldots\]

For a simple graph the process eventually exhausts its eligible edges; for a multigraph it can continue indefinitely. In both models, connectivity settles this event exactly: additional edges can never split a connected component. A successful simulation therefore checks every accepted edge through connectivity. A failed trial can stop immediately.

Why reporting at selected times misses the event

The introduction recounts a misleading interpretation of 1988 student experiments: reports at selected edge counts were taken to describe the whole evolution. Short intervals of coexistence can lie between reports. At the critical snapshot, the different event “at most one complex component” has probability near 0.9957. That number describes neither experiment on this page. Introduction, pages 2–3.

The product and its gamma evaluation

A limiting state can be indexed by the numbers \([r_1,r_2,\ldots]\) of complex components with positive excess \(1,2,\ldots\), with total excess \(r=\sum j r_j\). The top line has one complex component carrying all excess. On that line the limiting probability of moving from excess \(r\) to \(r+1\) without introducing a second complex component is

\[q_r=\frac{r(r+1)}{(r+1/6)(r+5/6)},\qquad r\ge1.\]

The first values are \(q_1=72/77\) and \(q_2=216/221\). The complementary probability simplifies to

\[1-q_r=\frac{5}{(6r+1)(6r+5)}.\]

At general states there can also be mergers and growth of existing complex components. Theorem 9 gives limiting transition probabilities; Theorem 10 in Section 17 establishes the asymptotic Markov description on any fixed number of excess levels, including independence from the route to the current state in the required limiting sense. These are transitions indexed by changes of excess, not by every accepted edge.

Conditional multiplication along the top line gives the finite product \(Q_R=\prod_{r=1}^R q_r\). The elementary gamma product identity is

\[\prod_{r=1}^R(r+a)=\frac{\Gamma(R+1+a)}{\Gamma(1+a)}.\]

Applying it to numerator and denominator gives

\[Q_R=\frac{\Gamma(R+1)\Gamma(R+2)\Gamma(7/6)\Gamma(11/6)}{\Gamma(1)\Gamma(2)\Gamma(R+7/6)\Gamma(R+11/6)}.\]

The gamma-ratio relation \(\Gamma(R+a)/\Gamma(R+b)\sim R^{a-b}\) makes the remaining large-\(R\) factor tend to one: the powers \(-1/6\) and \(+1/6\) cancel. Then recurrence and reflection yield

\[\lim_{R\to\infty}Q_R=\Gamma(7/6)\Gamma(11/6)=\frac5{36}\Gamma(1/6)\Gamma(5/6)\] \[=\frac5{36}\frac\pi{\sin(\pi/6)}=\frac{5\pi}{18}.\]

This is the exact evaluation of the infinite product in (18.1). It is not an exact probability for finite \(n\). Fixed-level convergence alone establishes the upper-bound direction: surviving the whole history requires surviving its first \(R\) levels. One must additionally rule out a substantial chance of a late departure.

How Section 27 closes the gap

Section 27 bounds late creation of a new complex component after \(m=\tfrac12(n+\alpha n^{2/3})\) by \(O(\alpha^{-3})\). If \(V_{mn}\) is the number of vertices in unicyclic components, a new complex component requires both endpoints to lie in that part, giving multigraph birth probability \(E[V_{mn}^2]/n^2\). Choose a late-window cutoff and an excess cutoff to make the omitted probability small, then let \(n\) grow at fixed cutoffs. Theorem 15 completes the equality for both models. Section 19's monotonicity argument concerns clean conditional transitions; it should not be read as a universal finite-size correction for this simulation.

The displayed gamma algebra is complete. The bounds linking the finite process to the infinite chain are summarized here; their detailed analytic proof remains in Section 27. No overall \(O(n^{-1/3})\) convergence rate for \(\Pr(B_n)\) is asserted on this page.

These are not competing estimates of the same probability. Their component restrictions are different, as are their observation windows. Neither event contains the other in general: two bicyclic components can satisfy the snapshot condition but violate the trajectory condition; a single increasingly complex component can respect the trajectory condition but violate the snapshot condition.

The critical graph can have several substantial contenders before a dominant component emerges. An instantaneous component census describes that configuration; a path event describes how it arose. Sparse early cyclic structure therefore contains information that a final connected graph alone cannot recover.

Monte Carlo uncertainty versus finite-size discrepancy

At each fixed \(n\), model and experiment, let \(I_j\) be independent success indicators with probability \(p_n\). The estimator and its variance are

\[\widehat p_n=\frac1R\sum_{j=1}^R I_j,\qquad E[\widehat p_n]=p_n,\qquad \operatorname{Var}(\widehat p_n)=\frac{p_n(1-p_n)}R.\] \[\widehat{\mathrm{SE}}=\sqrt{\widehat p_n(1-\widehat p_n)/R}.\]

Independent pseudorandom trial streams implement the usual Monte Carlo approximation to independent sampling. The standard error shrinks like \(R^{-1/2}\), while increasing \(n\) changes the probability being estimated. At these trial counts, small apparent increases or decreases across adjacent sizes need not describe a genuine convergence pattern.

\[\widehat p_n-p_\infty=\underbrace{(\widehat p_n-p_n)}_{\text{Monte Carlo error}}+\underbrace{(p_n-p_\infty)}_{\text{finite-size effect}}.\]

The Wilson interval comes from inverting the binomial score test. With \(z=1.959963984540054\), its centre and half-width are

\[c=\frac{\widehat p+z^2/(2R)}{1+z^2/R},\qquad h=\frac{z}{1+z^2/R}\sqrt{\frac{\widehat p(1-\widehat p)}R+\frac{z^2}{4R^2}},\qquad [c-h,c+h].\]

Wilson intervals stay within [0,1] and avoid the collapsed zero-width Wald interval when every trial succeeds. They have approximate, not exact, 95% binomial coverage. Each interval targets its finite-\(n\) \(p_n\); it is not automatically an interval for \(p_\infty\). The 60 intervals are pointwise and carry no simultaneous-coverage claim. A reference line outside a finite-size interval does not disprove an asymptotic theorem.

Equation (11.7) supplies a finite-size order \(O(n^{-1/3})\). For Theorem 15, the proof combines several cutoffs and limiting operations; borrowing the snapshot rate would be unjustified. Absolute deviations in the exports combine both sources of error and are not an estimate of a proven convergence exponent.

Reproducibility · Algorithms, data and executable source

From exact events to published results

Validated embedded simulation results. Exact JSON and CSV are linked below.

The results comprise 60,000 executed trials: both experiments × both models × 15 sizes × 1,000 repetitions. The Python computation uses NumPy arrays, Numba-compiled union-find and four parallel workers. Component vertex and edge counts live at roots; an edge update removes old roots' complex indicators and adds the updated indicator. This avoids scanning all vertices after every edge.

Simple-graph rejection stores only accepted unordered pairs in a hash set. Multigraph trials need no edge set. Memory is linear in vertices plus accepted simple-graph edges, rather than quadratic in \(n\). Snapshot classification scans roots once. Trajectory counts update incrementally. The exact early-stopping rules preserve both event definitions.

Executed configuration. Base seed 20261012; 1,000 trials per cell; batches of 100; four Numba threads. All 60,000 uint32 trial seeds were checked for collisions. from __future__ import annotations

import argparse
import math

import matplotlib.pyplot as plt

from matplotlib.animation import FFMpegWriter, FuncAnimation, PillowWriter


@dataclass(frozen=True)
class GiantComponentEvent:
    edge_index: int
    label: str


def layered_circular_layout(
    n: int,
    rng: np.random.Generator,
    outer_radius: float = 0.96,
    inner_radius: float = 0.55,
) -> Dict[int, Tuple[float, float]]:
    """Mostly circular shell with several nodes scattered inside."""
    if n <= 0:
        return {}

    outer_count = max(12, int(round(0.62 * n)))
    outer_count = min(outer_count, max(3, n - 2))

    points: List[Tuple[float, float]] = []

    angle_offset = float(rng.uniform(0.0, 2.0 * math.pi))
    outer_angles = np.linspace(0.0, 2.0 * math.pi, outer_count, endpoint=False) + angle_offset
    outer_angles += rng.normal(0.0, 0.07, size=outer_count)

    for theta in outer_angles:
        r = float(np.clip(outer_radius * (1.0 + rng.normal(0.0, 0.05)), 0.82, 1.02))
        points.append((r * math.cos(theta), r * math.sin(theta)))

    min_dist = 0.075 if n >= 100 else 0.12
    attempts = 0
    while len(points) < n and attempts < 25000:
        attempts += 1
        theta = float(rng.uniform(0.0, 2.0 * math.pi))
        r = float(inner_radius * math.sqrt(rng.uniform(0.0, 1.0)))
        x = r * math.cos(theta)
        y = r * math.sin(theta)
        if all((x - px) ** 2 + (y - py) ** 2 >= min_dist ** 2 for px, py in points):
            points.append((x, y))

    while len(points) < n:
        theta = float(rng.uniform(0.0, 2.0 * math.pi))
        r = float(inner_radius * math.sqrt(rng.uniform(0.0, 1.0)))

def collect_events(
    nodes: List[int],
    edges_in_order: List[Tuple[int, int]],
    giant_fraction: float,
) -> Tuple[List[GiantComponentEvent], int]:
    g = nx.Graph()
    g.add_nodes_from(nodes)
    events: List[GiantComponentEvent] = []

    giant_threshold = math.ceil(giant_fraction * len(nodes))
    first_giant_edge = len(edges_in_order)

    first_cycle = False
    crossed_quarter = False
    crossed_half = False
    first_giant = False

    for idx, edge in enumerate(edges_in_order, start=1):
        g.add_edge(*edge)
        largest_size = max((len(comp) for comp in nx.connected_components(g)), default=1)

        if not first_cycle and g.number_of_edges() >= g.number_of_nodes() and len(nx.cycle_basis(g)) > 0:
            first_cycle = True
            events.append(GiantComponentEvent(idx, "First cycle appears"))

        if not crossed_quarter and largest_size >= math.ceil(0.25 * len(nodes)):
            crossed_quarter = True
            events.append(GiantComponentEvent(idx, f"Largest component reaches {largest_size} vertices"))

        if not crossed_half and largest_size >= math.ceil(0.50 * len(nodes)):
            crossed_half = True
            events.append(GiantComponentEvent(idx, f"Component exceeds half the graph (size {largest_size})"))

        if not first_giant and largest_size >= giant_threshold:
            first_giant = True
            first_giant_edge = idx
            events.append(
                GiantComponentEvent(
                    idx,
                    f"Giant component emerges at size {largest_size} (threshold {giant_threshold})",
                )
            )
            break

    return events, first_giant_edge

def layered_circular_layout(
    n: int,
    rng: np.random.Generator,
    outer_radius: float = 0.96,
    inner_radius: float = 0.55,
) -> Dict[int, Tuple[float, float]]:
    if n <= 0:
        return {}

    outer_count = max(12, int(round(0.62 * n)))
    outer_count = min(outer_count, max(3, n - 2))

    points: List[Tuple[float, float]] = []

    angle_offset = float(rng.uniform(0.0, 2.0 * math.pi))
    outer_angles = np.linspace(0.0, 2.0 * math.pi, outer_count, endpoint=False) + angle_offset
    outer_angles += rng.normal(0.0, 0.07, size=outer_count)

    for theta in outer_angles:
        r = float(np.clip(outer_radius * (1.0 + rng.normal(0.0, 0.05)), 0.82, 1.02))
        points.append((r * math.cos(theta), r * math.sin(theta)))

    min_dist = 0.075 if n >= 100 else 0.12
    attempts = 0
    while len(points) < n and attempts < 25000:
        attempts += 1
        theta = float(rng.uniform(0.0, 2.0 * math.pi))
        r = float(inner_radius * math.sqrt(rng.uniform(0.0, 1.0)))
        x = r * math.cos(theta)
        y = r * math.sin(theta)
        if all((x - px) ** 2 + (y - py) ** 2 >= min_dist**2 for px, py in points):
            points.append((x, y))

    while len(points) < n:
        theta = float(rng.uniform(0.0, 2.0 * math.pi))
        r = float(inner_radius * math.sqrt(rng.uniform(0.0, 1.0)))
        points.append((r * math.cos(theta), r * math.sin(theta)))

    return {i: points[i] for i in range(n)}

def classify_component_types(g: nx.Graph) -> ComponentTypeSummary:
    """
    For each connected component H:
        excess(H) = |E(H)| - |V(H)| + 1

    excess = 0  -> tree
    excess = 1  -> unicyclic
    excess = 2  -> bicyclic
    excess >= 3 -> complex

    Isolated vertices count as tree components.
    """
    tree_count = 0
    unicyclic_count = 0
    bicyclic_count = 0
    complex_count = 0

    for component_nodes in nx.connected_components(g):
        h = g.subgraph(component_nodes)
        v = h.number_of_nodes()
        e = h.number_of_edges()
        excess = e - v + 1

        if excess == 0:
            tree_count += 1
        elif excess == 1:
            unicyclic_count += 1
        elif excess == 2:
            bicyclic_count += 1
        else:
            complex_count += 1

    return ComponentTypeSummary(
        tree_count=tree_count,
        unicyclic_count=unicyclic_count,
        bicyclic_count=bicyclic_count,
        complex_count=complex_count,
    )

    max_edges: int,

def layered_circular_layout(
    n: int,
    rng: np.random.Generator,
    outer_radius: float = 0.96,
    inner_radius: float = 0.55,
) -> Dict[int, Tuple[float, float]]:
    if n <= 0:
        return {}

    outer_count = max(12, int(round(0.62 * n)))
    outer_count = min(outer_count, max(3, n - 2))

    points: List[Tuple[float, float]] = []

    angle_offset = float(rng.uniform(0.0, 2.0 * math.pi))
    outer_angles = np.linspace(0.0, 2.0 * math.pi, outer_count, endpoint=False) + angle_offset
    outer_angles += rng.normal(0.0, 0.07, size=outer_count)

    for theta in outer_angles:
        r = float(np.clip(outer_radius * (1.0 + rng.normal(0.0, 0.05)), 0.82, 1.02))
        points.append((r * math.cos(theta), r * math.sin(theta)))

    min_dist = 0.075 if n >= 100 else 0.12
    attempts = 0
    while len(points) < n and attempts < 25000:
        attempts += 1
        theta = float(rng.uniform(0.0, 2.0 * math.pi))
        r = float(inner_radius * math.sqrt(rng.uniform(0.0, 1.0)))
        x = r * math.cos(theta)
        y = r * math.sin(theta)
        if all((x - px) ** 2 + (y - py) ** 2 >= min_dist**2 for px, py in points):
            points.append((x, y))

    while len(points) < n:
        theta = float(rng.uniform(0.0, 2.0 * math.pi))
        r = float(inner_radius * math.sqrt(rng.uniform(0.0, 1.0)))
        points.append((r * math.cos(theta), r * math.sin(theta)))

    return {i: points[i] for i in range(n)}


def ordered_random_edges(nodes: List[int], rng: np.random.Generator) -> List[Tuple[int, int]]:
    edges = [(u, v) for i, u in enumerate(nodes) for v in nodes[i + 1 :]]
    rng.shuffle(edges)
    return edges


def build_graph_state(nodes: List[int], edges_in_order: List[Tuple[int, int]], edge_count: int) -> nx.Graph:
    g = nx.Graph()
    g.add_nodes_from(nodes)
    g.add_edges_from(edges_in_order[:edge_count])
    return g


def giant_component_nodes(g: nx.Graph) -> set[int]:
    components = list(nx.connected_components(g))
    if not components:
        return set()
    return set(max(components, key=len))


def giant_component_edge_lists(
    edges_present: List[Tuple[int, int]],
    giant_nodes: set[int],
) -> Tuple[List[Tuple[int, int]], List[Tuple[int, int]]]:
    inside: List[Tuple[int, int]] = []
    outside: List[Tuple[int, int]] = []
    for u, v in edges_present:
        if u in giant_nodes and v in giant_nodes:
            inside.append((u, v))
        else:
            outside.append((u, v))
    return inside, outside


def classify_component_types(g: nx.Graph) -> ComponentTypeSummary:
    """
    For each connected component H:
        excess(H) = |E(H)| - |V(H)| + 1

    excess = 0  -> tree
    excess = 1  -> unicyclic
    excess = 2  -> bicyclic
    excess >= 3 -> complex

    In the new event of interest, an "other" component means any connected
    component that is neither a tree nor unicyclic, i.e. excess >= 2.
    """
    tree_count = 0
    unicyclic_count = 0
    bicyclic_count = 0
    complex_count = 0

    for component_nodes in nx.connected_components(g):
        h = g.subgraph(component_nodes)
        v = h.number_of_nodes()
        e = h.number_of_edges()
        excess = e - v + 1

        if excess == 0:
            tree_count += 1
        elif excess == 1:
            unicyclic_count += 1
        elif excess == 2:
            bicyclic_count += 1
        else:
            complex_count += 1

    return ComponentTypeSummary(
        tree_count=tree_count,
        unicyclic_count=unicyclic_count,
        bicyclic_count=bicyclic_count,
        complex_count=complex_count,
    )


def latest_event_text(edge_count: int, events: List[AnimationEvent], linger_edges: int) -> str:
    active = [e for e in events if e.edge_index <= edge_count < e.edge_index + linger_edges]

def collect_events_until(
    nodes: List[int],
    edges_in_order: List[Tuple[int, int]],
    max_edges: int,
    checkpoint_edge: int,
) -> List[AnimationEvent]:
    g = nx.Graph()
    g.add_nodes_from(nodes)
    events: List[AnimationEvent] = []

    first_cycle = False
    first_unicyclic = False
    first_other = False
    second_other = False
    checkpoint_marked = False

    for idx, edge in enumerate(edges_in_order[:max_edges], start=1):
        g.add_edge(*edge)
        summary = classify_component_types(g)

        if not first_cycle and len(nx.cycle_basis(g)) > 0:
            first_cycle = True
            events.append(AnimationEvent(idx, "First cycle appears"))

        if not first_unicyclic and summary.has_unicyclic:
            first_unicyclic = True
            events.append(AnimationEvent(idx, "First unicyclic component appears"))

        if not first_other and summary.other_count >= 1:
            first_other = True
            events.append(AnimationEvent(idx, "First 'other' component appears (excess ≥ 2)"))

        if not second_other and summary.other_count >= 2:
            second_other = True
            events.append(AnimationEvent(idx, "A second 'other' component appears; condition now fails"))

        if not checkpoint_marked and idx == checkpoint_edge:
            checkpoint_marked = True
            events.append(AnimationEvent(idx, f"Checkpoint reached: m = n/2 = {checkpoint_edge}"))

        if idx == max_edges:
            events.append(AnimationEvent(idx, f"Stopped at m = {max_edges}"))

    return events


def choose_grid(num_runs: int, requested_cols: int) -> Tuple[int, int]:
    ncols = max(1, min(requested_cols, num_runs))
    nrows = math.ceil(num_runs / ncols)
    return nrows, ncols


def build_frame_schedule(
    max_edges: int,
    checkpoint_edge: int,
    frames_per_edge: int,
    checkpoint_pause_frames: int,
    hold_final_frames: int,
) -> List[int]:
    schedule: List[int] = [0]
    for edge_count in range(1, max_edges + 1):
        schedule.extend([edge_count] * frames_per_edge)
        if edge_count == checkpoint_edge:
            schedule.extend([edge_count] * checkpoint_pause_frames)
    schedule.extend([max_edges] * hold_final_frames)
    return schedule

def make_multi_run_animation(

class UnionFind:
    def __init__(self, n: int) -> None:
        self.parent = list(range(n))
        self.size = [1] * n
        self.edge_count = [0] * n

    def find(self, x: int) -> int:
        parent = self.parent
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def add_edge(self, u: int, v: int) -> None:
        ru = self.find(u)
        rv = self.find(v)

        if ru == rv:
            self.edge_count[ru] += 1
            return

        if self.size[ru] < self.size[rv]:
            ru, rv = rv, ru

        self.parent[rv] = ru
        self.size[ru] += self.size[rv]
        self.edge_count[ru] += self.edge_count[rv] + 1

    def all_components_have_excess_at_most_two(self) -> bool:
        for i, p in enumerate(self.parent):
            if i == p:
                excess = self.edge_count[i] - self.size[i] + 1
                if excess > 2:
                    return False
        return True


def sample_unique_edges_sparse(
    n: int,
    m: int,
    rng: np.random.Generator,
) -> set[tuple[int, int]]:
    """
    Sample m distinct undirected edges uniformly from K_n.

    In this sparse regime, rejection sampling with a Python set is workable.
    """
    edges: set[tuple[int, int]] = set()

    while len(edges) < m:
        remaining = m - len(edges)
        batch_size = min(max(64, 3 * remaining), 300_000)

        u = rng.integers(0, n, size=batch_size, dtype=np.int64)
        v = rng.integers(0, n, size=batch_size, dtype=np.int64)

        mask = u != v
        if not np.any(mask):
            continue

        u = u[mask]
        v = v[mask]

        a = np.minimum(u, v)
        b = np.maximum(u, v)

        for x, y in zip(a.tolist(), b.tolist()):
            edges.add((x, y))
            if len(edges) >= m:
                break

    return edges


def trial_success(
    n: int,
    m: int,
    rng: np.random.Generator,
) -> bool:
    uf = UnionFind(n)
    edges = sample_unique_edges_sparse(n=n, m=m, rng=rng)

    for u, v in edges:
        uf.add_edge(u, v)

    return uf.all_components_have_excess_at_most_two()


def simulate_probability(
    n: int,
    m: int,
    m_label: str,
    trials: int,
    rng: np.random.Generator,
) -> SimulationResult:
    successes = 0
    for _ in range(trials):
        if trial_success(n=n, m=m, rng=rng):
            successes += 1

    p_hat = successes / trials
    se = math.sqrt(p_hat * (1.0 - p_hat) / trials) if trials > 0 else 0.0
    ci_low = max(0.0, p_hat - 1.96 * se)
    ci_high = min(1.0, p_hat + 1.96 * se)

    return SimulationResult(
        n=n,
        m_label=m_label,
        m=m,
        trials=trials,
        successes=successes,
        probability=p_hat,
        standard_error=se,
        ci_low=ci_low,
        ci_high=ci_high,
    )


def build_m_values(n: int) -> list[tuple[str, int]]:

        if ru == rv:
            self.edge_count[ru] += 1
            return

        if self.size[ru] < self.size[rv]:
            ru, rv = rv, ru

        self.parent[rv] = ru
        self.size[ru] += self.size[rv]
        self.edge_count[ru] += self.edge_count[rv] + 1

    def has_trees_unicyclic_and_at_most_one_other_component(self) -> bool:
        """
        Return True iff the graph consists of tree components, unicyclic components,
        and at most one other connected component.

        For a connected component H, define
            excess(H) = |E(H)| - |V(H)| + 1.

        Then:
          excess = 0  -> tree
          excess = 1  -> unicyclic
          excess >= 2 -> "other component"

        The desired event is: number of components with excess >= 2 is at most 1.
        """
        other_components = 0
        for i, p in enumerate(self.parent):
            if i == p:
                excess = self.edge_count[i] - self.size[i] + 1
                if excess >= 2:
                    other_components += 1
                    if other_components > 1:
                        return False
        return True


def sample_unique_edges_sparse(
    n: int,
    m: int,
    rng: np.random.Generator,
) -> set[tuple[int, int]]:
    """
    Sample m distinct undirected edges uniformly from K_n.

    In this sparse regime, rejection sampling with a Python set remains workable.
    """
    edges: set[tuple[int, int]] = set()

    while len(edges) < m:
        remaining = m - len(edges)
        batch_size = min(max(64, 3 * remaining), 300_000)

        u = rng.integers(0, n, size=batch_size, dtype=np.int64)
        v = rng.integers(0, n, size=batch_size, dtype=np.int64)

        mask = u != v
        if not np.any(mask):
            continue

        u = u[mask]
        v = v[mask]

        a = np.minimum(u, v)
        b = np.maximum(u, v)

        for x, y in zip(a.tolist(), b.tolist()):
            edges.add((x, y))
            if len(edges) >= m:
                break

    return edges


def trial_success(
    n: int,
    m: int,
    rng: np.random.Generator,
) -> bool:
    uf = UnionFind(n)
    edges = sample_unique_edges_sparse(n=n, m=m, rng=rng)

    for u, v in edges:
        uf.add_edge(u, v)

    return uf.has_trees_unicyclic_and_at_most_one_other_component()


def simulate_probability(
    n: int,
    m: int,
    m_label: str,
    trials: int,
    rng: np.random.Generator,
) -> SimulationResult:
    successes = 0
    for _ in range(trials):
        if trial_success(n=n, m=m, rng=rng):
            successes += 1

    p_hat = successes / trials
    se = math.sqrt(p_hat * (1.0 - p_hat) / trials) if trials > 0 else 0.0
    ci_low = max(0.0, p_hat - 1.96 * se)
    ci_high = min(1.0, p_hat + 1.96 * se)

    return SimulationResult(
        n=n,
        m_label=m_label,
        m=m,
        trials=trials,
        successes=successes,
        probability=p_hat,
        standard_error=se,
        ci_low=ci_low,
        ci_high=ci_high,
    )

<section id="foundations" class="card research"><div class="eyebrow">Introduction · Why n/2 matters</div><h2>Edges, cycles and the critical window</h2><p>The average degree at edge count \(m\) is \(2m/n\). Thus \(m=n/2\) is the point where average degree reaches one. Below the transition, components mostly resemble trees with occasional cycles. In the critical window \(m=n/2+O(n^{2/3})\), component sizes and cyclic structures fluctuate substantially. Critical large components have scale \(n^{2/3}\); a giant in the macroscopic sense has size proportional to \(n\). Being complex does not by itself make a component a giant.</p><p>The classical permutation process gives a uniform simple graph \(G(n,m)\) at each accepted edge count. The 1993 paper also uses a weighted multigraph process. Their limits coincide for the two events studied here, while their finite-size probabilities can differ. All results below keep the processes separate. See <a href="https://arxiv.org/pdf/math/9310236#page=1">the paper's introduction</a> and <a href="https://arxiv.org/pdf/math/9310236#page=5">Section 1</a>.</p>

<div class="note"><strong>Bicyclic components are already complex.</strong> The complex condition is \(e>v\), equivalently \(\beta\ge2\). Size \(v\), edge count \(e\), cycle rank \(\beta\), and signed component excess \(e-v=\beta-1\) measure different things.</div>
<p>For a tree, signed component excess is −1; it is zero for a unicyclic component and positive for a complex component. Section 13's graph excess excludes the tree deficit. If \(t\) is the number of tree components, it is</p><div class="math">\[r(G)=m-n+t=\sum_H\max\{e_H-v_H,0\}.\]</div><p>This differs both from \(m-n\) and from total cycle rank \(\sum_H\beta(H)=m-n+k\), where \(k\) counts all components. The notation \(C_j\) in the paper describes connected components with positive excess \(j\), hence \(j+1\) independent cycles.</p>
<h3>What one accepted edge does</h3><p>If its endpoints already share a component, \(v\) stays fixed and \(e\) increases by one: \(\beta\) increases by one. This includes a self-loop. If it joins two components,</p><div class="math">\[v'=v_1+v_2,\qquad e'=e_1+e_2+1,\qquad \beta'=\beta_1+\beta_2.\]</div><p>A merger adds no new independent cycle. Joining two unicyclic components nevertheless produces a bicyclic component. Joining two complex components reduces the current complex-component count from two to one; it cannot undo their earlier coexistence.</p>
<h3>Two stochastic models, implemented exactly</h3><div class="table-wrap"><table class="compare"><thead><tr><th>Model</th><th>Accepted edge rule</th><th>Implication</th></tr></thead><tbody><tr><td>Simple graph / permutation</td><td>Independent uniform endpoint proposals; reject loops and previously accepted unordered pairs.</td><td>Each remaining pair has exactly two ordered proposals, so conditional acceptance is uniform among unused pairs. No list of all n(n−1)/2 pairs is allocated.</td></tr><tr><td>Uniform multigraph</td><td>Two independent uniform endpoints; accept every proposal.</td><td>A specific loop has probability 1/n²; a specific non-loop undirected edge has probability 2/n². Parallel edges are retained.</td></tr></tbody></table></div><p>This multigraph law is uniform over ordered endpoint sequences, not over distinct multigraph adjacency matrices. Different multigraphs have different sequence multiplicities; the paper's compensation factors encode them. Neither model uses vertex positions or preferential attachment.</p></section>

<div class="derivation"><h3>From connected-component enumeration to cosh</h3><p>The following coefficient identities specify the combinatorial calculation. Write \(T\) for the rooted labelled-tree generating function and \(U\) for unrooted trees. \[W(z)=\frac5{24}(1-T)^{-3}-\frac7{24}(1-T)^{-2}+\frac1{12}(1-T)^{-1}.\]</div><p>Here \(V\) enumerates connected unicyclic structures and \(W\) enumerates connected bicyclic structures. For exactly \(r\) bicyclic components and none of higher order, the number of tree components must be \(n-m+r\): summing \(e-v\) over components gives \(m-n=-t+r\). The labelled set construction then leads to the probability coefficient (11.2):</p><div class="math">\[\frac{2^m m!n!}{n^{2m}}[z^n]\frac{U(z)^{n-m+r}}{(n-m+r)!}\,e^{V(z)}\frac{W(z)^r}{r!}.\]</div><p>The factor \(e^V\) allows any number of unicyclic components; \(W^r/r!\) specifies exactly \(r\) bicyclic ones. Component labels are handled by the exponential generating functions. Near \(T=1\), the strongest singularity in \(W\) has coefficient \(5/24\) and order three. Theorem 4, using Lemma 3, evaluates the coefficient for fixed \(r\) and \(m=n/2+O(n^{1/3})\):</p><div class="math">\[\Pr(\text{exactly }r\text{ bicyclic, none higher})=\sqrt{\frac23}\frac{(5/18)^r}{(2r)!}+O(n^{-1/3}).\]</div><p>The factorial is consistent with the gamma duplication identity</p><div class="math">\[\Gamma(r+\tfrac12)=\frac{(2r)!\sqrt\pi}{4^r r!}.\]</div><p>The cosh step is now an elementary calculation:</p><div class="math">\[\sum_{r=0}^\infty\sqrt{\frac23}\frac{(5/18)^r}{(2r)!}=\sqrt{\frac23}\sum_{r=0}^\infty\frac{\bigl(\sqrt{5/18}\bigr)^{2r}}{(2r)!}=\sqrt{\frac23}\cosh\sqrt{\frac5{18}}.\]</div><p>Summing fixed-\(r\) limits alone does not prove this equals the event limit: probability could escape to configurations with unbounded \(r\). <div class="derivation"><h3>The product and its gamma evaluation</h3><p>A limiting state can be indexed by the numbers \([r_1,r_2,\ldots]\) of complex components with positive excess \(1,2,\ldots\), with total excess \(r=\sum j r_j\). The complementary probability simplifies to</p><div class="math">\[1-q_r=\frac{5}{(6r+1)(6r+5)}.\]</div><p>At general states there can also be mergers and growth of existing complex components. Theorem 9 gives limiting transition probabilities; Theorem 10 in Section 17 establishes the asymptotic Markov description on any fixed number of excess levels, including independence from the route to the current state in the required limiting sense. These are transitions indexed by changes of excess, not by every accepted edge.</p><p>Conditional multiplication along the top line gives the finite product \(Q_R=\prod_{r=1}^R q_r\). The elementary gamma product identity is</p><div class="math">\[\prod_{r=1}^R(r+a)=\frac{\Gamma(R+1+a)}{\Gamma(1+a)}.\]</div><p>Applying it to numerator and denominator gives</p><div class="math">\[Q_R=\frac{\Gamma(R+1)\Gamma(R+2)\Gamma(7/6)\Gamma(11/6)}{\Gamma(1)\Gamma(2)\Gamma(R+7/6)\Gamma(R+11/6)}.\]</div><p>The gamma-ratio relation \(\Gamma(R+a)/\Gamma(R+b)\sim R^{a-b}\) makes the remaining large-\(R\) factor tend to one: the powers \(-1/6\) and \(+1/6\) cancel. \[=\frac5{36}\frac\pi{\sin(\pi/6)}=\frac{5\pi}{18}.\]</div><p>This is the exact evaluation of the infinite product in (18.1). It is not an exact probability for finite \(n\). <h3>Monte Carlo uncertainty versus finite-size discrepancy</h3><p>At each fixed \(n\), model and experiment, let \(I_j\) be independent success indicators with probability \(p_n\). """Compiled independent trials; trajectory successes stop only at connectivity."""
import numpy as np
from numba import njit, prange
from .sampling import draw_edge
from .union_find import add_edge


@njit(cache=True)
def trial(n, simple, trajectory, seed):
    np.random.seed(seed)
    parent = np.arange(n)
    size = np.ones(n, np.int64)
    edges = np.zeros(n, np.int64)
    used = {np.int64(-1)}
    components, complex_count, m = n, 0, 0
    while True:
        if trajectory:
            if components == 1:
                return 1, m
        elif m == n // 2:
            for i in range(n):
                if parent[i] == i and edges[i] - size[i] + 1 > 2:
                    return 0, m
            return 1, m
        u, v = draw_edge(n, simple, used)
        complex_count, merged = add_edge(parent, size, edges, u, v, complex_count)
        components -= int(merged)
        m += 1
        if trajectory and complex_count >= 2:
            return 0, m

"""Exact lazy sampling of the two Section 1 graph processes."""
import numpy as np
from numba import njit


@njit(cache=True)
def draw_edge(n, simple, used):
    # Each unordered non-loop pair has two equally likely ordered proposals.
    # Conditional on acceptance every unused pair therefore has equal probability.
    while True:
        u = np.random.randint(n)
        v = np.random.randint(n)
        if not simple:
            return u, v
        if u == v:
            continue
        if u > v:
            u, v = v, u
        key = np.int64(u) * n + v
        if key not in used:
            used.add(key)
            return u, v


@njit(cache=True)
def sample_edges(n, m, simple, seed):
    """Validation helper; not used to materialize large research histories."""
    np.random.seed(seed)
    used = {np.int64(-1)}
    out = np.empty((m, 2), np.int64)
    for i in range(m):
        out[i] = draw_edge(n, simple, used)
    return out

"""Binomial Monte Carlo summaries; constants are limits, not finite-n targets."""
import math

LIMITS = {'snapshot': math.sqrt(2 / 3) * math.cosh(math.sqrt(5 / 18)),
          'trajectory': 5 * math.pi / 18}
NS = [50, 100, 500, 1000, 5000, 10000, 20000, 30000, 40000,
      50000, 60000, 70000, 80000, 90000, 100000]


def wilson(successes, trials):
    if not 0 <= successes <= trials or trials <= 0:
        raise ValueError('Invalid binomial counts')
    z = 1.959963984540054
    p = successes / trials
    d = 1 + z * z / trials
    c = (p + z * z / (2 * trials)) / d
    h = z / d * math.sqrt(p * (1 - p) / trials + z * z / (4 * trials * trials))
    return (0.0 if successes == 0 else max(0, c - h),
            1.0 if successes == trials else min(1, c + h))


def summarize(row):
    p = row['successes'] / row['trials']
    limit = LIMITS[row['experiment']]
    lo, hi = wilson(row['successes'], row['trials'])
    return dict(row, probability=p, theoretical_limit=limit,
                signed_difference=p-limit, absolute_difference=abs(p-limit),
                standard_error=math.sqrt(p*(1-p)/row['trials']), ci_low=lo, ci_high=hi)

def reference(n, history):
    adjacency = [set() for _ in range(n)]
    for u, v in history:
        adjacency[u].add(v)
        adjacency[v].add(u)
    unseen = set(range(n))
    components = []
    while unseen:
        reached, stack = set(), [next(iter(unseen))]
        while stack:
            u = stack.pop()
            if u in reached:
                continue
            reached.add(u)
            stack.extend(adjacency[u] - reached)
        unseen -= reached
        # Count original edge occurrences, so loops and parallel edges are exact.
        e = sum(u in reached and v in reached for u, v in history)
        components.append((len(reached), e))
    return components

"""Root vertex/edge counts and an incremental complex-component count."""
import numpy as np
from numba import njit


@njit(cache=True)
def find(parent, u):
    while parent[u] != u:
        parent[u] = parent[parent[u]]
        u = parent[u]
    return u


@njit(cache=True)
def add_edge(parent, size, edges, u, v, complex_count):
    a, b = find(parent, u), find(parent, v)
    complex_count -= int(edges[a] > size[a])
    merged = a != b
    if merged:
        complex_count -= int(edges[b] > size[b])
        if size[a] < size[b]:
            a, b = b, a
        parent[b] = a
        size[a] += size[b]
        edges[a] += edges[b] + 1
    else:
        edges[a] += 1
    complex_count += int(edges[a] > size[a])
    return complex_count, merged


@njit(cache=True)
def classify_history(n, history):
    """Return final snapshot event, persistent trajectory event, current count."""
    parent, size, edges = np.arange(n), np.ones(n, np.int64), np.zeros(n, np.int64)
    count, ever_failed = 0, False
    for u, v in history:
        count, _ = add_edge(parent, size, edges, u, v, count)
        ever_failed = ever_failed or count >= 2
    snapshot = True
    for i in range(n):
        if parent[i] == i and edges[i] - size[i] + 1 > 2:
            snapshot = False
    return snapshot, not ever_failed, count
