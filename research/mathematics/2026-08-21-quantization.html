Quantization replaces many possible values with a smaller set of allowed values. That single idea underlies everything from old audio recordings to modern large-language-model compression. This page builds the idea up slowly — starting with rounding a few everyday numbers, and ending with the low-bit formats used for neural-network inference.

1. What Is Quantization?

Suppose you measure six objects and record these values:

$$0.7 \quad 1.2 \quad 1.8 \quad 2.4 \quad 2.9 \quad 3.3$$

Now suppose you are only allowed to report whole numbers — the nearest integer to each measurement. The rule “round to the nearest allowed value” maps each real number to one of a small set of possibilities:

$$1 \quad 1 \quad 2 \quad 2 \quad 3 \quad 3$$

You started with six distinct measurements and ended with only three distinct reported values (1, 2, and 3). That is quantization. The stored numbers are close to the originals, but they are not exact. The gap between an original value and its stored stand-in is called the quantization error.

The mental model we will reuse all page long:
  1. Original values
  2. Choose the representable levels
  3. Map each value to the nearest level (a code)
  4. Store or compute using those codes
  5. Reconstruct approximate values when needed
  6. Measure the approximation error

2. Start With Rounding

Rounding is the simplest possible quantizer. You pick a fixed spacing between allowed values — here a spacing of $1$ — and you send every number to the closest multiple of that spacing. The distance between allowed values is the step size. A smaller step size means more allowed values, which generally means smaller error.

3. Think in Buckets

Rounding to whole numbers hides a useful picture. Imagine laying a ruler down and drawing boundaries every $1$ unit. Each stretch between two boundaries is a bucket. Every value that falls inside a bucket is reported by the same representative — usually the bucket's center or its lower edge.

The number of buckets is the number of allowed levels. Fewer buckets means a coarser map; more buckets means a finer map. The widget below lets you choose how many levels cover the range $0$ to $10$.

3.1 Decision cells and reconstruction values

Think of a postal address: many physical positions share one address. A scalar quantizer similarly assigns every input in a region to one representative. The index identifies that region; the reconstruction is the numerical value used after decoding.

$$Q:\mathbb R\to\mathcal C,\qquad \mathcal C=\{c_0,\ldots,c_{L-1}\},\qquad Q(x)=c_k\ \text{if }x\in R_k.$$

The decision regions $R_k$ form a disjoint partition of the input domain. A finite codebook has $L$ reconstruction values; a countably infinite lattice such as $\Delta\mathbb Z$ cannot encode every index with a fixed finite number of bits when inputs are unbounded. For ordered nearest-neighbour levels, thresholds lie at $t_k=(c_{k-1}+c_k)/2$. Assign a threshold tie to the upper cell: $R_k=[t_k,t_{k+1})$, with infinite outer endpoints.

3.2 A finite uniform quantizer, completely specified

Throughout the bit-depth comparison and numerical audit, $[a,b]=[-1,1]$ is the design interval, $L$ is the number of equal-width cells, and each cell reconstructs to its midpoint. Inputs outside the interval saturate to the first or last center. Every input and output in these experiments is dimensionless unless a physical unit is explicitly given.

$$\Delta=\frac{b-a}{L},\quad k(x)=\operatorname{clip}_{[0,L-1]}\left(\left\lfloor\frac{x-a}{\Delta}\right\rfloor\right),\quad Q(x)=a+\left(k(x)+\frac12\right)\Delta.$$

At $x=b$ the clipped index is $L-1$; at an interior threshold the upper cell wins. With $L=8$, $x=0.37$ gives $k=5$, $Q(x)=0.3750$ and $e=-0.0050$. With $x=1.4$ the reconstruction remains $0.8750$, so the granular bound $|e|\le\Delta/2$ no longer applies.

Two valid spacings. Midpoint cells covering a design interval use $\Delta=(b-a)/L$. Endpoint-inclusive levels spanning two extreme reconstructions use $\Delta=(c_{\max}-c_{\min})/(L-1)$. The sine-wave figure below uses the latter. Confusing the two changes the level count and endpoint behavior.

3.3 Staircases, thresholds and signed error

A mid-tread quantizer has a level at zero; a mid-rise quantizer has a threshold at zero. Before saturation their rules are $Q_t(x)=\Delta\lfloor x/\Delta+1/2\rfloor$ and $Q_r(x)=\Delta(\lfloor x/\Delta\rfloor+1/2)$. Exact ties go toward the larger reconstruction. Here the permitted lattice levels are restricted to [−1,1], while the plotted input extends beyond it.

4. From Buckets to Levels

A key realization: once you fix the range and the number of levels, the exact values inside do not matter for naming a level. You only need to know which bucket a number falls into. The stored information is the bucket index, not the original number.

So the real question becomes: how many different levels (buckets) do we need, and how do we write them down efficiently? That is where bits enter.

Floating point vs integer. FP32 and FP16 are floating-point formats: they store a sign, an exponent, and a mantissa, so they can represent a very wide range of magnitudes with varying precision. INT8 and INT4 are integer quantization formats: they store a small whole-number code that is later mapped back to a real value through a scale (and possibly a zero-point). They are not simply “FP16 with fewer bits” — they are a different way of encoding numbers.

8. The Quantization Equation

Now we make the bucket idea precise. The standard affine quantization rule maps a real value $x$ to an integer code $q$:

$$q = \operatorname{clip}_{[q_{\min},q_{\max}]}\!\left(\left\lfloor\frac{x}{s}+\frac12\right\rfloor + z\right)$$

and recovers an approximation $\hat{x}$ from the code:

$$\hat{x} = s\,(q - z)$$

where

  • $x$ is the original real value,
  • $q$ is the stored integer code,
  • $s$ is the scale (how much real distance one code step covers),
  • $z$ is the zero-point (which code represents real value $0$).

Worked example. Take $x = 3.72$, $s = 0.25$, and $z = 0$.

  • Divide: $\dfrac{x}{s} = \dfrac{3.72}{0.25} = 14.88$.
  • Round and add zero-point: $q = \operatorname{round}(14.88) + 0 = 15$.
  • Reconstruct: $\hat{x} = s\,(q - z) = 0.25 \times 15 = 3.75$.
  • Error: $e = x - \hat{x} = 3.72 - 3.75 = -0.03$.

The stored information is just the integer 15; the scale $0.25$ and zero-point $0$ are shared metadata that let us get back close to the original.

For this example the code range is $0,\ldots,15$, so the reconstruction range is $[0,3.75]$ and no clipping occurs. The quantization error is defined as

$$e = x - \hat{x}.$$

8.1 Code ranges, ties and zero

The displayed implementation uses $\lfloor u+1/2\rfloor$ for nearest rounding: a tie at −1.5 becomes −1. Hardware may instead use ties-to-even, so a deployed format must specify this choice. Clipping happens after rounding and the integer zero-point shift.

# unsigned affine calibration, including zero
L ← 2^b; a ← min(0, xmin); bmax ← max(0, xmax)
s ← (bmax − a) / (L − 1)            # use s=1 for an all-zero range
z ← clip(floor(−a/s + 1/2), 0, L−1)
q ← clip(floor(x/s + 1/2) + z, 0, L−1)
xhat ← s * (q − z); e ← x − xhat

Each scalar costs O(1) once calibration is known. Finding extrema costs O(N). The narrow signed symmetric convention here uses $q\in[-(2^{b-1}-1),2^{b-1}-1]$, $z=0$: one bit pattern is unused. Its one-bit zero-inclusive limit has only the level zero, rather than dividing by zero. A binary ±A quantizer is a different, zero-excluding design.

9. Scale

The scale $s$ decides how much real-world distance each code step covers. If your data ranges from $x_{\min}$ to $x_{\max}$ and you have integer codes from $q_{\min}$ to $q_{\max}$, an endpoint-inclusive spacing is (use the zero-expanded calibration range for the affine widgets):

$$s = \frac{x_{\max} - x_{\min}}{\,q_{\max} - q_{\min}\,}.$$

Geometrically this is a straight-line map between two number lines: the top line is the real-value range, the bottom line is the integer-code range, and reconstruction has slope $s$ in real units per code; the unrounded encoding map has reciprocal slope $1/s$.

10. Zero-Point

The zero-point $z$ is the integer code that represents the real value $0$. It matters when your data does not straddle zero symmetrically. In the unsigned affine convention used here, calibration first includes zero: $a=\min(0,x_{\min})$, $b=\max(0,x_{\max})$. For positive-only data, $z=0$ and codes cover nonnegative values. An endpoint-fitted quantizer with an arbitrary real offset is a different convention.

Symmetric vs asymmetric in one sentence. A symmetric quantizer forces the real value $0$ to map exactly to the center code, which is simple but can waste codes when data is one-sided. An asymmetric quantizer uses the zero-point to slide the mapping so that $0$ lands on whatever code is convenient, making better use of the available levels for non-centered data.

11. Symmetric vs Asymmetric Quantization

The two strategies behave differently on the same data. Below, the same set of values is shown under both schemes. Symmetric keeps zero fixed at the center; asymmetric shifts the zero-point to use more codes on the occupied side, subject to including zero and integer zero-point rounding.

12. Quantization Error

There are really two different kinds of error, and it helps to keep them separate.

Rounding (discretization) error

This is the normal, unavoidable gap between a real value and the nearest allowed level. With a good range and $L$ levels, the maximum absolute granular error is $s/2$ when each input lies within half a step of a reconstruction level. More levels shrink it; fewer levels grow it.

Clipping (saturation) error

This happens when a value lies outside the representable range entirely. It is clamped to the nearest endpoint, and no amount of extra levels inside the range fixes it. The fix is to choose a better range — not just more levels.

12.1 From one error to expected distortion

A quantizer can be accurate for common values and poor for rare ones. Mean squared distortion weights squared error by how often each input occurs. If amplitudes have units of volts, distortion has units of volts squared.

$$D=\mathbb E[(X-Q(X))^2]=\sum_{k=0}^{L-1}\int_{R_k}(x-c_k)^2 f_X(x)\,dx,\qquad \widehat D=\frac1N\sum_{n=1}^{N}(x_n-Q(x_n))^2.$$

Here $f_X$ is the input density, $R_k$ is a decision region and $c_k$ its reconstruction. The integral includes overload tails when the source has support outside the design range. The sample average $\widehat D$ is an empirical estimate, not a population identity.

12.2 Deriving Δ²/12 and the ideal sine-wave SQNR

If a cell's density is approximately constant and its center reconstructs the input, its conditional error is approximately uniform on $[-\Delta/2,\Delta/2]$. Integrating the squared gap gives

$$\mathbb E[e^2\mid R_k]\approx\frac1\Delta\int_{-\Delta/2}^{\Delta/2}u^2\,du=\frac1\Delta\left[\frac{u^3}{3}\right]_{-\Delta/2}^{\Delta/2}=\frac{\Delta^2}{12}.$$

This is exact for a uniform source tiled by equal midpoint cells without overload. It is a high-resolution approximation for a smooth density that changes little across each cell. Coarse cells, concentrated inputs, clipping and deterministic signal–error correlation can invalidate the noise model. Rounding error is not automatically independent of the signal.

Derive the familiar 6.02b + 1.76 dB rule

A full-scale sine $X=A\sin\theta$ has mean power $A^2/2$ when phase is uniformly distributed. For $2^b$ midpoint cells on $[-A,A]$, $\Delta=2A/2^b$. Under the ideal high-resolution error model,

$$\mathrm{SQNR}\approx\frac{A^2/2}{\Delta^2/12}=\frac32\,2^{2b},\quad 10\log_{10}\mathrm{SQNR}\approx6.0206b+1.7609\ \mathrm{dB}.$$

Each extra bit ideally quarters distortion over a fixed range. Lower signal amplitude, overload, a different source distribution or correlated error changes this result.

12.3 Nonuniform cells and Lloyd–Max optimization

Spend reconstruction levels where squared error is costly. For fixed decision regions, differentiating their distortion with respect to $c_k$ yields $2\int_{R_k}(c_k-x)f_X(x)dx=0$, so the best level is the conditional mean. For fixed levels, choose the nearest one point by point.

$$t_k=\frac{c_{k-1}+c_k}{2},\qquad c_k=\frac{\int_{t_k}^{t_{k+1}}x f_X(x)\,dx}{\int_{t_k}^{t_{k+1}} f_X(x)\,dx}.$$

Alternate these two updates. Each exact subproblem cannot increase distortion, but the joint problem is nonconvex: convergence need not produce a global optimum. An empty cell retains its old level here. For a uniform source on [−1,1] with initial levels −0.8 and 0.4, the threshold is −0.2; their centroids become −0.6 and 0.4, and the new threshold becomes −0.1. Repetition approaches −0.5 and 0.5.

For $N$ quadrature points and $L$ levels, the direct search used here costs $O(NL)$ per iteration and $O(N+L)$ memory. Sorted scalar levels permit $O(N\log L)$ assignments by binary search. Use an improvement tolerance and an iteration limit in production.

12.4 Representation cost and the rate–distortion boundary

Our fixed-length code costs $b=\lceil\log_2 L\rceil$ bits per sample, plus codebook or scale metadata. A nonuniform occupancy can support a smaller average label length through entropy coding: $H(K)=-\sum_k p_k\log_2 p_k$, with prefix-code average length between $H(K)$ and $H(K)+1$ for an optimal binary code under the usual conditions. This changes encoding, not the already reconstructed values.

For a memoryless source and additive per-sample distortion, Shannon's $R(D)=\inf_{p(\hat x\mid x):\,\mathbb E[d(X,\hat X)]\le D}I(X;\hat X)$ is a theoretical asymptotic limit for a specified source and distortion measure, permitting long block codes. Here $I$ is mutual information, $p(\hat x\mid x)$ is a conditional reconstruction law, and $d(x,\hat x)=(x-\hat x)^2$ for the squared-error case. A finite scalar quantizer and its plotted distortion do not generally attain that boundary.

Dither: when the uniform-noise interpretation can be justified

For an infinite uniform lattice with spacing Δ, subtractive dither reconstructs $\hat x=Q(x+U)-U$, where $U$ is independently uniform over one quantization interval and is known to the decoder. With no overload, the resulting signed error is uniform on an interval of width Δ and independent of x. Nonsubtractive dither reconstructs $Q(x+U)$ and leaves the added noise in the output; it does not inherit the same error variance or independence guarantee. Finite-range clipping breaks the simple subtractive result.

14.1 Quantizing a vector jointly

The preceding widget rounds each coordinate separately. True vector quantization selects one whole vector from a codebook $\mathcal C\subset\mathbb R^d$: $Q(\mathbf x)=\arg\min_{\mathbf c\in\mathcal C}\|\mathbf x-\mathbf c\|_2^2$. In two dimensions its decision cells are Voronoi regions. Four vector codewords need two bits per vector; independently quantizing each of two coordinates to four levels needs four bits per vector and allows sixteen reconstructions.

16. One Scale or Many?

So far we used one scale for an entire array. That is called per-tensor quantization, and it is simplest. But real weight matrices often have rows or channels with very different ranges. Look at the two channels below:

$$\text{Channel A: } 0.01\;\; 0.03\;\; 0.05\;\; 0.08 \qquad \text{Channel B: } 2.1\;\; 4.3\;\; 6.7\;\; 9.2$$

With one global scale, Channel A's tiny values all collapse into a single level — most of its precision is wasted. Giving each channel its own scale uses the available levels where they are needed.

Give each channel its own ruler. The small channel now uses its own fine reconstruction grid; the larger channel keeps its wider range. Store the scale and zero-point alongside each channel.

19. Per-Group Quantization

Per-group: one scale per small group

A middle ground used by modern methods (e.g. group-wise INT4): split each channel into small groups and give each group its own scale. This localizes the effect of outliers.

20. From Matrices to Neural Networks

A trained neural network is, at its core, a large collection of numerical parameters (weights) plus the intermediate numbers computed as data flows through it (activations). Matrix multiplication with weight matrices is the dominant operation. Everything we did to the small matrix above is exactly what happens, at scale, inside an LLM — except there are billions of entries instead of nine.

21. Weights and Activations

Weights are fixed after training; they are known ahead of time and easy to calibrate. Activations are produced fresh for every input and can vary widely, which makes them harder to quantize well. Modern systems often treat the two differently.

24. Weight-Only Quantization

A model does not have to quantize every numerical object. The simplest practical choice is weight-only quantization: compress the stored weights to low bits, but keep activations (the numbers flowing through the network) at higher precision. This saves disk and memory bandwidth for the weights while leaving the arithmetic mostly unchanged.

25. Weight and Activation Quantization

Going further, both weights and activations can be quantized. This can accelerate inference when the hardware and kernels execute the dominant matrix multiplications efficiently in low precision. It is harder, because activations vary per input and are prone to outliers.

Conceptually: weight-only changes how weights are stored; weight-and-activation changes how the computation is done. The second usually saves more, but is more sensitive to outliers and hardware support.

26. Post-Training Quantization (PTQ)

Post-Training Quantization is applied after a model has already been trained. You take the float weights, pick a scheme (e.g. per-channel INT4), and convert them, usually using a small calibration set to choose good ranges. It is fast and cheap, but the model itself never “knew” it would be quantized.

PTQ pipeline: trained float model → choose ranges (calibration) → compute scales/zero-points → store low-bit weights → run (dequantize as needed). No retraining required.

27. Calibration

Calibration answers a question we already met back in the clipping section: what range should the levels cover? A badly chosen range wastes codes or clips values. A good range uses the available levels efficiently.

  • Bad range → excessive clipping of ordinary values.
  • Range too wide → quantization levels are spread too thinly, so rounding error grows.
  • Well chosen range → better use of available codes.

PTQ typically uses a representative sample of real inputs to estimate each tensor's range — exactly the scale/zero-point reasoning from Section 9.

28. Quantization-Aware Training (QAT)

Quantization-Aware Training bakes quantization into the training (or fine-tuning) process. The forward pass simulates rounding and clipping, so the model learns weights that survive low-bit storage with less damage. It costs more than PTQ but can preserve more accuracy at very low bit widths.

QAT pipeline: train/fine-tune with a “fake quant” operation that rounds → the model adapts → export low-bit weights. Slower, but the network accounts for quantization during learning.

29. Outliers

A small number of unusually large values can wreck low-bit quantization. Suppose almost every value sits near zero, but one point is far away. The global scale is then forced to be huge, so the near-zero values fall into a single coarse level — their detail is destroyed, even though they carry most of the information.

Outlier effect on scale

Increase the outlier and watch the scale balloon: the many small values are crushed into fewer effective levels. This is why modern methods use per-channel/per-group scales or special outlier handling instead of one global min/max.

30. 8-Bit and 4-Bit Models

Two bit widths dominate practical discussion. INT8 is the classic “safe” compression: 8 bits (256 levels) usually preserves accuracy well and is widely supported in hardware. INT4 (16 levels) is the aggressive option that fits huge models into consumer hardware, at the cost of more care about ranges, outliers, and sometimes extra metadata.

31. INT8, INT4, FP8, FP4 and NF4

The alphabet soup of low-bit formats each solves a slightly different problem:

  • INT8 — uniform signed/unsigned 8-bit integers; simple encoding; accuracy and speed depend on calibration and kernels.
  • INT4 — uniform 4-bit integers; very compact, needs careful scaling.
  • FP8 — an 8-bit floating-point format (e.g. E4M3/E5M2); keeps an exponent so it covers a wide range with modest precision.
  • FP4 — a 4-bit floating-point format; very few representable states; exact layout and hardware support depend on the format.
  • NF4 — NormalFloat 4-bit: not uniform integers, but levels spaced to match the bell-shaped distribution of trained weights (see below).

32. Modern LLM Quantization Methods

The techniques below are all attempts to make the fundamental trade-off (precision vs size) work for billion-parameter models. They differ in what they quantize and how they choose scales — not in the underlying idea from the top of this page.

33. What Quantization Does NOT Mean

Misconception: “INT4 means every original weight must literally be an integer between −8 and 7.”
The stored code is an integer in that range, but it participates in a mapping $\hat{x}=s(q-z)$. The original weight was a float; the code identifies a reconstruction level. Unsigned formats instead use codes 0 through 15, and the narrow signed convention on this page uses −7 through 7.
Misconception: “Going from FP16 to 4-bit makes every program four times faster.”
Fewer bits reduce memory and can speed up bandwidth-bound ops, but actual speed depends on hardware, kernels, and whether compute runs in low precision. Not a guaranteed 4×.
Misconception: “Quantization is lossless compression.”
It is an approximation. The reconstructed value $\hat{x}$ differs from $x$; that gap is the quantization error we measured throughout.
Misconception: “Lower precision is always worse.”
Many tasks tolerate tiny numerical differences in exchange for large efficiency gains. The right bit width is a deliberate engineering choice.
Misconception: “Quantization only matters for AI.”
It is a classical signal-processing and numerical idea: audio CD resolution, image formats, and sensor readings all rely on choosing representable levels.

34. The Fundamental Trade-Off

Reducing bits trades several things against each other. None of them moves in isolation, and fewer bits do not automatically mean proportional speed:

  • Numerical precision ↓ as bits ↓
  • Distortion — more optimally placed levels can improve the best achievable error; arbitrary grids need not improve every input.
  • Model size / memory ↓ roughly with bits
  • Memory bandwidth ↓ (less data to move)
  • Computational efficiency — only if hardware/kernel supports the format
  • Hardware support — support varies by device, format and kernel
  • Implementation complexity ↑ for per-group/outlier methods
  • Accuracy / model quality — may drop at very low bits

Real speedup depends on hardware, kernels, memory bandwidth, model architecture, the quantization format, and the software implementation. The claim “4-bit = four times faster than 16-bit” is not generally true.

35. Summary / Mental Model

We started by rounding a few everyday numbers. Every later idea was the same operation dressed for a harder setting:

The mental model, restated:
  1. Original values (a signal, a vector, a weight matrix)
  2. Choose the representable levels (via range, bits, scale, zero-point)
  3. Map each value to the nearest code (with or without a zero-point shift)
  4. Store or compute using those codes (per-tensor, per-channel, or per-group)
  5. Reconstruct approximate values when needed ($\hat{x}=s(q-z)$)
  6. Measure and manage the error — rounding, clipping, outliers
