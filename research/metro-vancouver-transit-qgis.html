01 — Install the tools
Terminal

Start with Ubuntu, QGIS LTR, and OpenCode

This walkthrough records Ubuntu 24.04 noble, QGIS 3.44.13 Solothurn LTR, and OpenCode. Run each block in a terminal. The QGIS commands use its official signed repository rather than UbuntuGIS or an unofficial package source.

Install QGIS from the official LTR repository

sudo apt update
sudo apt install curl gnupg software-properties-common wget

sudo mkdir -m755 -p /etc/apt/keyrings
sudo wget -O /etc/apt/keyrings/qgis-archive-keyring.gpg \
  https://download.qgis.org/downloads/qgis-archive-keyring.gpg

sudo tee /etc/apt/sources.list.d/qgis.sources >/dev/null <<EOF
Types: deb deb-src
URIs: https://qgis.org/ubuntu-ltr
Suites: noble
Architectures: amd64
Components: main
Signed-By: /etc/apt/keyrings/qgis-archive-keyring.gpg
EOF

sudo apt update
sudo apt install qgis qgis-plugin-grass
qgis --version
Checkpoint

QGIS is ready when the terminal prints a QGIS version and the application opens to its welcome screen without a package error.

These commands reproduce the recorded 64-bit Ubuntu environment. For a later release or another architecture, use the values in the current QGIS Debian/Ubuntu installation guide.

Install and verify OpenCode

curl -fsSL https://opencode.ai/install | bash
opencode --version

OpenCode is ready when opencode --version prints a version number and running opencode opens its terminal interface.

03 — Make your first QGIS map
QGIS / Manual

Open the application before studying the data model

Launch QGIS from the Applications menu or run qgis. Choose New Empty Project, then use Project → Save As and save metro-vancouver-transit.qgz inside research/GIS Learning/qgis/.

Browser

Find files, databases, and XYZ tiles.

Layers

Control draw order, visibility, and selection.

Map canvas

Pan, zoom, select, and inspect.

Layer Properties

Double-click a layer to configure styling, labels, rendering, source filters, and related settings.

Status bar

Read scale, coordinates, and project CRS.

If Browser or Layers is missing, enable it from View → Panels. Toolbars can be restored from View → Toolbars.

Load the prepared GeoJSON layers

  1. Choose Layer → Add Layer → Add Vector Layer.
  2. Browse to data/processed/transit_routes_simplified.geojson and click Add.
  3. Repeat for data/processed/transit_stops.geojson.
  4. Optionally load transit_route_patterns.geojson, but leave it unchecked; it contains every route variant.
  5. Drag layers so stops draw above routes.

Add OpenStreetMap

In Browser, expand XYZ Tiles and double-click OpenStreetMap. Drag it below the vector layers. QGIS reads the GeoJSON in WGS 84 and reprojects it on the fly for the basemap-driven map canvas.

What just happened? The data are not broken. QGIS is simply rendering all 8,907 stop, station, and entrance records with the same symbol and equal visual importance. Filtering, scale visibility, and distinct markers will turn this dense first view into a readable hierarchy.

Checkpoint

Your first map is loaded when the Layers panel lists routes, stops, and OpenStreetMap, and the canvas shows dense purple points over route lines and the basemap.

Save often. Press Ctrl+S after adding layers and after each styling stage. A .qgz stores references and cartographic decisions, not duplicate GeoJSON.
04 — Understand the GTFS data

The lines on screen came from related text tables

GTFS Static is a collection of CSV-formatted text tables, not a ready-made GIS layer. A row in routes.txt identifies a public-facing service, but its travelled path arrives through trips and ordered shape points. Stop order is a separate relationship.

trips.txtConnects routes, service IDs, directions, and shapes65,431 rows
shapes.txtOrdered WGS 84 points used to create lines215,714 rows; 1,041 shapes
stops.txtStops, platforms, stations, and entrances8,907 rows
stop_times.txtOrdered stop visits for each trip1,873,506 rows
calendar*.txtRegular service patterns and date exceptions43 services; 702 exceptions

Why a transit route is not just one line

A single route can have two directions, short turns, branches, alternate terminals, and service-specific variants. GTFS represents each path as a separate shape_id. Concatenating all shapes for one route would create jumps and malformed geometry.

p1, p2, …, pn ordered by shape_pt_sequence  →  L = (p1, p2, …, pn)

Detailed route patterns

transit_route_patterns.geojson preserves 1,040 unique route/shape/direction combinations and their supporting trip counts. It is the audit-friendly layer.

Representative routes

transit_routes_simplified.geojson contains 482 selected route-direction lines for a cleaner overview. Here “simplified” means fewer variants, not reduced vertices.

The representative rule chooses the shape with the highest trip count within each route and direction, then breaks ties by greater source point count and finally ascending shape_id. Opposite directions remain separate.

One explicit exclusion. HandyDART shape 4484 contains one point and is used by one trip. A one-point path cannot form a LineString, so it is documented rather than replaced with invented geometry. HandyDART remains in the 244-row route summary.
05 — How the geometry was built
OpenCode / Automated

A small, ordered processing pipeline

Each script has one teaching purpose. Paths are derived with pathlib, optional GTFS tables are discovered dynamically, and validation compares the outputs back to the retained archive.

ScriptResponsibility
01_download_gtfs.pyDownload, checksum, validate, date, and extract the immutable ZIP.
02_inspect_gtfs.pyInventory tables, counts, fields, bounds, and missing values.
03_build_routes.pyBuild detailed LineStrings and deterministic representatives.
04_build_stops.pyConvert all stop-location records into WGS 84 points.
05_build_route_summary.pyJoin trip, stop, service, shape, and projected-length statistics.
06_validate_outputs.pyVerify provenance, relationships, geometry, CRS, selections, and summaries.

Build one shape

points = points.sort_values(
    "shape_pt_sequence", kind="stable"
)
coordinates = list(zip(
    points["shape_pt_lon"],
    points["shape_pt_lat"]
))
geometry = LineString(coordinates)

Count meaningful patterns

combinations = (
    trips.groupby([
        "route_id", "shape_id", "direction_id"
    ])
    .size()
    .rename("trip_count")
    .reset_index()
)

Measure in metres, publish in longitude/latitude

GeoJSON stays in WGS 84 longitude/latitude, represented as OGC CRS84 and interpreted compatibly by GeoPandas/QGIS as EPSG:4326. Distance is different: degrees are angular units, not planar metres. Selected lines are temporarily reprojected to NAD83 / UTM zone 10N (EPSG:26910).

Lr = Σi=1n-1 d(pi, pi+1)   in EPSG:26910, then metres ÷ 1000
Do this manually instead: reconstruct shapes.txt in QGIS
  1. Extract the GTFS ZIP without editing the retained archive.
  2. Choose Layer → Add Layer → Add Delimited Text Layer and open shapes.txt.
  3. Set X to shape_pt_lon, Y to shape_pt_lat, and geometry CRS to EPSG:4326.
  4. Open Processing Toolbox and run Points to Path.
  5. Use shape_id as the group field and numeric shape_pt_sequence as the order field.
  6. Join the paths to an aggregated trips.txt table by shape_id, then join route attributes from routes.txt by route_id.
  7. Load stops.txt separately with X stop_lon, Y stop_lat, and EPSG:4326.
  8. Export both outputs as GeoJSON in EPSG:4326.

Verify numeric sequence order, keep each shape_id separate, and confirm that joins did not multiply geometry. The automated workflow is preferable because these checks are reproducible.

07 — Control point clutter
QGIS / Manual

Turn one source layer into three map roles

location_type changes the meaning of a point. This feed contains 8,720 ordinary stops/platforms, 60 stations, and 127 entrances/exits. Keeping the distinctions allows the map to reveal detail progressively.

ValueMeaningFeaturesSuggested visibility
0Stop or platform8,720Approximately 1:40,000 or closer
1Station60Regional marker; labels after zooming in
2Entrance or exit127Very close detail, around 1:10,000

Rename the original layer Transit Stops. Duplicate it twice and rename the copies Transit Stations and Transit Entrances. For each layer, open Layer Properties → Source, click Query Builder, and apply its expression:

"location_type" = '0'   -- Transit Stops
"location_type" = '1'   -- Transit Stations
"location_type" = '2'   -- Transit Entrances

In Symbology, give stations a 2.2 mm white circle with a dark outline, ordinary stops a small muted circle, and entrances a distinct close-detail marker. Keep stations visible regionally; show ordinary stops around 1:40,000 or closer and entrances around 1:10,000 or closer.

10 — Export with qgis2web
QGIS / Manual

Translate the project with qgis2web

qgis2web packages vector data, styles, controls, and Leaflet into static files that GitHub Pages can serve. Open Plugins → Manage and Install Plugins, search for qgis2web, install it, then choose Web → qgis2web → Create web map.

  1. Choose Leaflet and a folder export.
  2. Enable minified GeoJSON and use the current map-canvas extent.
  3. Keep OpenStreetMap visible as the basemap.
  4. Export the route, station, stop, and entrance layers; leave clustering off for stations.
  5. Choose useful popup fields, retain the layer control, and export to web/qgis2web/.

Why opening index.html directly failed

When the export was opened through a file:// URL, OpenStreetMap rejected tile requests because the required HTTP referrer context was absent. The vector overlays loaded, but repeated 403 tiles obscured the map.

cd "research/GIS Learning/web/qgis2web"
python3 -m http.server 8000

# Then open:
http://localhost:8000
Checkpoint

The web export works when web/qgis2web/index.html exists and the localhost page shows OpenStreetMap, transit routes, station markers, labels, and a working layer control without tile errors.

This server is only for testing on the local machine. GitHub Pages provides the HTTP hosting after publication.
